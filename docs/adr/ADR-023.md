# ADR-023 · 安装与部署：安装/卸载脚本、systemd --user unit 与崩溃重启

状态：采纳（M2-T14，随任务分步补全）

## 背景

M2-T14 的验收是 AC-005-04（TEST-005-04，检查 `recovery`）与 AC-005-06（TEST-005-06，检查 `deployment`）。done_when 另要求：

- systemd --user unit（Restart=on-failure、有界 StartLimit、Delegate=yes；CR-011：host 在受委托的 cgroup 中运行，Attempt 以其 cgroup 证明终结）随安装脚本落地；
- deployment 检查脚本落地：tests/check-plan.json 不再指向 not-implemented.sh，并产出 test-results.jsonl。

需求依据：

- REQ-005 行为 6：长期服务由 systemd --user 托管（Restart=on-failure、有界 StartLimit，ExecStart 为隐藏 daemon 入口）；logout 后持续运行仅在用户明确启用 linger 时配置。
- REQ-005 决定 4：StartLimitBurst=5、StartLimitIntervalSec=300、RestartSec=5 s（初值）。
- REQ-005 行为 2：Shell 退出、SSH 断开不影响已接受任务。
- REQ-005 行为 4、失败模式 4、5：host 先取项目锁、host_epoch+1、reconcile，之后才接受写命令；同项目并发启动只留一个 host；崩溃后由 systemd 重启，先 reconcile。
- docs/11「生产构建目标」：安装到 ~/.local/bin，资源按版本目录，current 原子切换，现有用户覆盖文件不覆盖。
- docs/11「后台运行」：ExecStart 只用已安装的受支持隐藏入口，unit 带 `Delegate=yes`。

起点（main b1da7a6，M2-T07 已合入）：

- **打包**：`scripts/product/build.sh` 在 run_check 下打 `hoh-release.tar.gz`（hoh/bin/hoh、LICENSE、THIRD_PARTY_NOTICES.md、resources/）。`scripts/install.sh` 存在时，它被放进包里作 `hoh/install.sh`。
- **检查计划**：`deployment` 指向 not-implemented.sh；`recovery` 只跑 `cargo test -p hoh-app --test recovery`；integration 跑 `--test '*'`。
- **版本**：`help::version()` 输出 `hoh <semver>\ncore <v>, agents <v>\n`，没有 commit。AC-062-05 的扫描禁止 workspace 中有任何 build script（`persistence_scan.py`，M2T01R-33），所以不能用 build.rs 嵌入 commit。
- **客户端**：`client::ensure` 先探测，再对项目目录加 flock（最多 10 s，每 20 ms 一次），锁内再探测一次，然后 `start`。`start` 在 cgroup v2、`$XDG_RUNTIME_DIR/systemd/private`、linger、systemd-run 都满足时用受委托 scope，否则直接拉起。就绪的判定：`host.json` 的 pid 等于子进程 pid，且 `/healthz` 返回 200（ADR-021 决定 2）。
- **host 的退出码**：SIGTERM 或 SIGINT 为 0；writer 结束为 1；参数不对为 64；项目被另一个 host 持有为 69；位置或 WAL 拒绝为 78。HTTP 停止宽限 5 s（`SHUTDOWN_GRACE`）。
- **M2-T07**：`__host` 用 `HostConfig::product(project, config, gate = current_exe(), path = $PATH)`。执行器按 host 的 PATH 找 claude/codex/pi，经 `hoh __gate` 启动。ADR-022 决定 17：host 崩溃后，STARTED 而没有观察到结果的 Attempt 由 reconcile 记为 UNKNOWN_EFFECT。
- **预研**（`.hoh-dev/evidence/m2t14-prep/`）：在 `systemd-run --user --scope -p Delegate=yes` 内可以运行一个私有的 `systemd --user`（env -i、临时 HOME、短 XDG_RUNTIME_DIR）。`systemctl --user` 以同一环境与它通信，它能加载并启动 unit；`Delegate=yes` 的服务能在自己的 cgroup 下建子 cgroup；kill -9 MainPID 后 NRestarts=1；`systemctl --user exit` 之后，真实管理器中不留下 unit。2026-11-09 在本 VM（systemd 259）与 GitHub 的 ubuntu-24.04 runner（systemd 255，run 42690870866，临时分支，日志在 `ci-spike/`）上各跑一次，结果相同。私有管理器会在运行时目录下建权限为 000 的 `systemd/inaccessible/*`，拆除时须先 `chmod -R u+rwX` 再删除。

## 决定

1. **unit 模板 `hoh-host@.service`**（REQ-005 行为 6、决定 4；CR-011）

   内容由二进制生成（`hoh __unit template`，见决定 5）。安装脚本把它写到 `$XDG_DATA_HOME/systemd/user/hoh-host@.service`，默认 `~/.local/share/systemd/user`；systemd.unit(5) 把这个目录定为「在家目录中安装的软件包的 unit」。

   ```ini
   # Written by the HoH installer at each install, removed by `install.sh --uninstall`.
   # Local changes belong in drop-ins: systemctl --user edit hoh-host@.service
   [Unit]
   Description=HoH host (project %i)
   StartLimitIntervalSec=300
   StartLimitBurst=5

   [Service]
   Type=exec
   EnvironmentFile=%S/hoh/hosts/%i.env
   ExecStart="/home/<user>/.local/bin/hoh" __host ${HOH_PROJECT}
   Restart=on-failure
   RestartSec=5
   RestartPreventExitStatus=64 69 78
   Delegate=yes
   KillMode=control-group
   TimeoutStopSec=15
   StandardInput=null
   StandardOutput=null
   StandardError=append:%t/hoh-host@%i.stderr

   [Install]
   WantedBy=default.target
   ```

   取舍：

   - **重启与限速**：Restart=on-failure、RestartSec=5、StartLimitBurst=5、StartLimitIntervalSec=300，都是 REQ-005 行为 6 与决定 4 的原值。
   - **ExecStart**：
     - 已安装的 `$HOME/.local/bin/hoh`（AC-005-06：「ExecStart 指向已安装二进制」），加上 ADR-021 决定 1 的 `__host <项目绝对路径>`，不新增 daemon 入口。
     - 生成时写成加双引号的绝对路径，转义 `%`→`%%`、`$`→`$$`、`\`、`"`；HOME 不是 UTF-8 或含换行时拒绝。
     - 不用 `%h`：它是「运行该管理器的用户的家目录」。私有管理器下若它取 passwd 而不取 `$HOME`，ExecStart 就会指到真实 HOME 中的 hoh，破坏测试隔离。
   - **`${HOH_PROJECT}`**：整个值作一个参数（systemd.service(5)），路径中的空格保留。
   - **Type=exec**：exec 失败时 `systemctl start` 就失败。就绪仍由客户端判断（决定 6），不实现 sd_notify：reconcile 可能先停旧进程（每级 5 s），Type=notify 的启动超时会与它耦合。
   - **RestartPreventExitStatus=64 69 78**：这三种退出不是崩溃，重启也不会改变结论。不阻止的话，它们每 5 s 重试一次，直到碰到 StartLimit。
     - 64：参数不对，例如项目目录已删除；
     - 69：项目已被另一个 host 持有（REQ-005 失败模式 4）；
     - 78：位置或 WAL 拒绝。

     SIGKILL、退出码 1（writer 结束，M2T12R-150）与 panic 照常重启。
   - **Delegate=yes**：done_when 与 CR-011 的要求。host 的 `Delegated::detect` 在自己的 cgroup（`…/hoh-host@<h>.service`）下建 `attempt-*`。不启用 controller，所以 host 留在该 cgroup 的根上，不违反 no-internal-process 规则。不用 DelegateSubgroup（systemd 254 才有）。
   - **KillMode=control-group**（默认值，显式写出）：
     - host 崩溃或被停止时，systemd 对 unit cgroup 中剩下的进程（各 Attempt）发 SIGTERM，TimeoutStopSec 之后发 SIGKILL，cgroup 清空后才重启。
     - 所以新 host 的 reconcile 看到旧 Attempt 的 cgroup 已删除或为空，按 ADR-021 决定 8d 直接得到证明。M2T06R-1001 关于同名 scope 重建的规则，对同名 service cgroup 同样适用。
     - 不用 process 或 none：进程会逃出 unit 的生命周期（systemd.kill(5)），停止 unit 或卸载都停不掉 Agent。
     - 不用 mixed：崩溃时剩下的进程直接收到 SIGKILL，没有宽限。
   - **TimeoutStopSec=15**：
     - 正常停止需要 HTTP 的 5 s 宽限，加上 writer 的最后一次写；
     - 同时为崩溃路径设上界：Agent 忽略 SIGTERM 时，从 kill 到重启最坏约 15 + 5 s，加上 host 启动，仍在 AC-005-04 的 30 s 之内。
   - **标准流**：
     - stdin、stdout 为 /dev/null（ADR-021 决定 1）；
     - stderr 在 ready 之前追加到 `%t/hoh-host@<h>.stderr`。该文件在运行时目录中，管理器退出时清除；
     - ready 之后，host 照旧把 stderr dup2 到 `.hoh/host.log`；
     - 客户端读这个文件的末行取得拒绝的码，与直接拉起时读管道相同，不依赖 journald。
   - **启用**：`WantedBy=default.target`，启用的实例随用户管理器启动；有 linger 时即开机启动。

2. **实例名与项目**（AC-005-06：`hoh-host@<项目 hash>.service`）
   - **实例名**：项目规范路径的字节取 sha256，前 16 个十六进制字符。规范路径用 `canonicalize`，与客户端的 `here()` 一致；命名方式与 Attempt cgroup 相同。实例名只由 `hoh_app::unit::instance` 计算。
   - **映射**：每个实例一个 EnvironmentFile `$XDG_STATE_HOME/hoh/hosts/<h>.env`，模板中写作 `%S/hoh/hosts/%i.env`。
     - 文件权限 0600，目录 0700。
     - 内容两行：`HOH_PROJECT="…"`、`PATH="…"`，双引号内按 systemd.exec(5) 的规则转义 `\ " $` 与反引号。
     - systemd 要求该文件是 UTF-8。路径或 PATH 不是 UTF-8 时不用 unit（决定 6 回退）。
     - 先写临时文件再 rename：自动重启时 systemd 会在启动前重读它。
     - 同一 hash 的文件中已经是另一个路径时（碰撞），拒绝，不覆盖。
   - **缺失时**：没有该文件，实例无法启动；`HOH_PROJECT` 指向的目录不存在时，`__host` 以 64 退出，不重启。
   - **PATH 如何到达 host**：用户管理器的环境里没有登录 shell 的 PATH，而执行器按 host 的 PATH 找 Agent（ADR-022 决定 10、17）。
     - `install.sh --project` 写入安装时的 PATH；
     - 客户端每次经 unit 拉起 host 之前写入自己的 PATH。这在项目锁内进行，此时没有 host 在运行；
     - 这与 ADR-021 直接拉起时 host 继承客户端环境的语义一致；开机启动的实例用最近一次写入的 PATH。
   - **只传 PATH 与 HOH_PROJECT**：不复制 API key、代理等环境变量，HoH 不把凭证写进文件（docs/11）。
     - 原生登录（凭证在 HOME 下）不受影响；
     - 依赖环境变量认证的用户，用 `~/.config/environment.d/*.conf` 或 `systemctl --user edit` 的 drop-in；
     - docs/11、docs/12 写明。

3. **安装脚本 `scripts/install.sh`**（包内为 `hoh/install.sh`）

   用法：`install.sh [--project <目录>]... [--linger]`，以及 `install.sh --uninstall`。

   - **root**：euid 为 0 时以 77 退出，什么也不写（与 bootstrap 同理）。全程不调用 sudo（AC-005-06）。
   - **布局**（XDG 变量未设时取默认值）：

     ```
     $XDG_DATA_HOME/hoh/versions/<semver>-<sha256(bin/hoh) 前 12 位>/   包的全部内容（bin/hoh、resources/、LICENSE、
                                                                          THIRD_PARTY_NOTICES.md、install.sh、web/ 若有）
     $XDG_DATA_HOME/hoh/current -> versions/<…>                           新符号链接 rename 覆盖（mv -T），原子切换
     $HOME/.local/bin/hoh -> $XDG_DATA_HOME/hoh/current/bin/hoh
     $XDG_DATA_HOME/systemd/user/hoh-host@.service                        `hoh __unit template` 的输出，内容变化时才 rename 覆盖
     $XDG_STATE_HOME/hoh/hosts/<h>.env                                    每个实例一个（决定 2）
     ```

     `~/.local/bin` 是 AC-005-06 规定的位置（`command -v hoh` = `$HOME/.local/bin/hoh`）。
   - **版本目录**：按二进制内容命名，一旦写成就不再修改。
     - 先复制到 `versions/.tmp.<pid>`，再 rename；同名目录已存在即为同一内容，跳过。
     - 旧版本目录保留到卸载：运行中 host 的 `current_exe()` 与 `__gate` 都指向它自己的版本目录，删除后它就不能再启动 Agent；回滚也需要（docs/11）。
   - **不覆盖用户的东西**（docs/11）：
     - `~/.local/bin/hoh` 已存在且不是指向本安装的符号链接时，以 1 退出，什么也不改；
     - 从不写 drop-in（`~/.config/systemd/user/hoh-host@.service.d/`）、`~/.config/hoh/` 与项目的 `.hoh/`；
     - 存在整份覆盖的 `~/.config/systemd/user/hoh-host@.service` 时照常安装，但提示它优先于安装的模板。
   - **管理器可达时**（`$XDG_RUNTIME_DIR/systemd/private` 存在）：
     - 执行 `systemctl --user daemon-reload`；
     - 再用 `systemctl --user show -p FragmentPath,LoadState hoh-host@x.service` 确认管理器读到的就是刚写的文件。管理器的 XDG_DATA_HOME 与 shell 不同时读不到，此时以 69 退出，已写的文件保留。
   - **`--project <目录>`**（可重复）：
     - 对每个目录执行已安装的 `hoh __unit enable <目录>`：写 env 文件，执行 `systemctl --user enable hoh-host@<h>.service`。
     - 不加 `--now`：host 在第一次客户端调用或下次管理器启动时启动。
     - 只在用户已开启 linger 时启用。否则管理器在最后一个会话结束时连同 host 一起停止，SSH 断开会中断已接受的任务（REQ-005 行为 2，M2T06R-453）。这时报错并提示 `--linger`，以 69 退出，已装文件保留。
   - **`--linger`**：执行 `loginctl enable-linger "$USER"`，是否允许由 polkit 决定，不用 sudo。只在用户明确给出时配置（REQ-005 行为 6）。
   - **不给 `--project`**：不启用任何实例，也不从当前目录推断。
   - **幂等**：同一个包再执行一次，文件、链接、模板与启用状态都不变；模板相同时不重写，也不 daemon-reload。
   - **输出**：结尾打印版本（`hoh --version` 的前两行）、linger 状态与启用的实例。
   - **自删除**：脚本主体包在 `main "$@"; exit` 中，bash 先读完整个脚本；卸载会删除 `current/install.sh` 自己。

4. **卸载 `install.sh --uninstall`**（AC-005-06：二进制与 unit 删除，项目 `.hoh/` 原样保留）

   按顺序：

   1. 管理器可达时，取实例集合：`hosts/*.env` 的名字，并上 `systemctl --user list-units --all --plain --no-legend 'hoh-host@*.service'` 列出的。逐个执行 `disable --now`：host 正常停止，KillMode 停掉它的 Attempt 进程。最后执行 `reset-failed`。
   2. 删除模板，执行 `daemon-reload`；删除 `hosts/` 与 `$XDG_RUNTIME_DIR/hoh-host@*.stderr`。
   3. 删除 `~/.local/bin/hoh`（只在它是指向本安装的链接时）与 `$XDG_DATA_HOME/hoh/`。
   4. 不动 linger、drop-in、`~/.config/hoh/` 和任何项目的 `.hoh/`。脚本根本不读项目路径。
   5. 仍在运行、不受 unit 管理的 `hoh __host` 进程只列出提示，不杀。

   没有安装时什么也不做，以 0 退出。

5. **隐藏入口 `hoh __unit`**

   与 ADR-021 决定 1 的做法相同：`main` 在 `cli::parse` 之前识别它，帮助与补全中不出现，参数不对时以 64 退出。

   - `hoh __unit template`：按 `$HOME` 输出决定 1 的模板。
   - `hoh __unit enable <目录>`：
     1. 规范化目录，计算实例名；
     2. 经 `systemctl --user show` 取该实例的 EnvironmentFiles 路径，写入 env 文件；
     3. 执行 `systemctl --user enable`。

     管理器不可达或用户没有 linger 时以 69 退出；路径不能用于 unit（不是 UTF-8，或 hash 碰撞）时以 78 退出。
   - 模块 `hoh_app::unit` 是实例名、模板、env 文件格式与 `systemctl show` 解析的唯一实现，客户端与 doctor 共用。

6. **客户端拉起 host**（修订 ADR-021 决定 2 的第 4 步；启动锁与就绪判定不变）

   在项目锁内、再次探测没有 host 之后：

   1. **unit**。以下条件全部满足时使用：
      - ADR-021 已有的条件：cgroup v2、`$XDG_RUNTIME_DIR/systemd/private` 存在、用户已开启 linger；另外 `systemctl` 在 PATH 上；
      - 本进程就是已安装的 hoh：`current_exe()` 的规范路径等于 `$HOME/.local/bin/hoh` 的规范路径。所以开发构建与 cargo 测试不会碰用户安装的 unit，也不会去查询真实管理器；
      - `systemctl --user show -p LoadState,ExecStart,EnvironmentFiles hoh-host@<h>.service`（经 probe runner，限时 2 s）得到 loaded，且 ExecStart 的 `path=` 规范化后等于 `current_exe()`；
      - 项目路径与 PATH 都是 UTF-8。

      使用时的步骤：
      1. 写 env 文件；
      2. 执行 `systemctl --user start hoh-host@<h>.service`，限时到 10 s 期限；
      3. 读 `MainPID`；
      4. 每 20 ms 查看一次，直到 `host.json` 的 pid 等于 MainPID 且 `/healthz` 返回 200。这就是 ADR-021 决定 2 第 5 步的判定，只把子进程 pid 换成 MainPID。
   2. **否则按 ADR-021 决定 2**：先尝试受委托 scope，不行再直接拉起。不用 unit 的原因经新环境变量 `HOH_HOST_UNSUPERVISED` 交给 host，与 `HOH_HOST_UNSCOPED` 的做法相同。

   失败的处理：

   - **unit 可用但 `systemctl start` 失败**（StartLimit 已满、exec 失败、env 文件读不了）：以 69 退出，消息带 unit 的 `Result`，并提示 `systemctl --user status hoh-host@<h>.service`。不回退：StartLimit 是有意设的刹车（「有界 StartLimit」），回退会让崩溃循环换个方式继续。
   - **MainPID 在就绪之前结束**：读 `ExecMainStatus`。
     - 69：另一个 host 持有项目，再探测并连接它；
     - 78：码取 stderr 文件末行（`refused_code`）；
     - 其他：以 69 退出，消息带该末行。

     systemd 自动重启时 MainPID 会变，客户端跟随新的 MainPID，直到期限。
   - **只有一个 host**：systemd 自动重启的 host 与客户端回退拉起的 host 同时出现时，由 `.hoh` 上的 flock 决定，输者以 69 退出。unit 的 host 因 RestartPreventExitStatus 不再重启；客户端按第 6 步连接胜者。所以仍然只有一个 host（AC-005-02 的性质）。
   - **没有启用的实例**：照样可以 start。崩溃重启只要求 unit 在运行，不要求启用。
   - **RestartSec 窗口内调用客户端**：`systemctl start` 立即启动，取消自动重启的计时。结果相同：一个 host，先 reconcile。

7. **host 侧**
   - `__host` 在参数检查之后把 cwd 设为项目目录。unit 下的默认 cwd 是 HOME，直接拉起时是项目目录（ADR-021 决定 2），这样两条路径一致。
   - `host.json` 增加 `supervisor` 字段：
     - `/proc/self/cgroup` 的末段形如 `hoh-host@<16 hex>.service` 时，写该 unit 名；
     - 否则写 null，`supervision_reason` 写客户端给的 `HOH_HOST_UNSUPERVISED`；没有时写「not started by its systemd unit」。
   - `hoh doctor` 的 `runtime.host` 增加附加字段 `supervisor` 与 `supervision_detail`。没有 host 运行时，按决定 6 第 1 步的检查报告预期（注明未经验证）；不可用时加一条警告，例如没有 linger 时，崩溃后不会自动重启。
   - unit 下的 `process_tracking` 为 cgroup，不需要 systemd-run。ADR-021 决定 8d 的余项不变。

8. **`hoh --version` 带候选 commit**（AC-005-06）
   - **输出**：改为三行：
     1. `hoh <semver>`；
     2. `commit <40 位十六进制>[-dirty]`，或 `commit unknown`；
     3. `core <v>, agents <v>`。

     第一行不变，`tests/cli.rs` 与 `help::tests` 断言它恰为 semver。
   - **嵌入**：用 `option_env!("HOH_BUILD_COMMIT")`，运行时只接受 `^[0-9a-f]{40}(-dirty)?$`，其他值都显示为 unknown。不用 build.rs，原因见背景（AC-062-05，M2T01R-33）。
   - **来源**：被 source 的 `scripts/product/build-commit.sh` 导出 `HOH_BUILD_COMMIT=$(git rev-parse HEAD)`，已跟踪文件有改动时加 `-dirty`。`build.sh` 与 `deployment.sh` 在调用 cargo 之前 source 它。候选的检出是干净的（`tools/candidate.py verify`），所以候选的包输出候选的 `git_commit`。

9. **发布包与 deployment 检查**
   - **bundle.sh**：`build.sh` 的打包部分移到 `scripts/product/bundle.sh <输出.tar.gz>`。同一提交下，重构前后的 tarball sha256 相同。
   - **deployment.sh**：check-plan 中的 `deployment` 改为 `["bash", "scripts/product/deployment.sh"]`，artifacts 不变。步骤：
     1. source build-commit.sh；有 `HOH_CANDIDATE_FILE` 时，其 `git_commit` 必须等于 HEAD；
     2. `cargo build --workspace --release --locked`，用 `bundle.sh` 把包写到 `/tmp` 下的临时目录；
     3. `HOH_RELEASE_BUNDLE=… HOH_EXPECTED_COMMIT=… cargo test -p hoh-app --locked --test deployment -- --include-ignored --test-threads=1`；
     4. 在 run_check 下由 `test_results.py` 写 `test-results.jsonl`，测试失败时也写；
     5. 没有测试通过，或没有 TEST-005-06 的 PASS 行时，以 3 失败（NO_TESTS）。

     脚本不写仓库内的任何文件（run_check 会核对 source_unchanged）。
   - **检查自己打包的原因**：run_check 只给本检查一个证据目录，没有引用其他检查产物的机制。包由同一脚本、同一候选生成，tar 可复现。测试把所用包的 sha256 记入观察。

10. **测试隔离：私有用户管理器**

    依据 TEST-005-06 的夹具（「临时 HOME（XDG_* 指向临时目录）、systemd --user」），并且不碰正在运行的服务。

    - **位置**：共享模块 `crates/hoh-app/tests/systemd/mod.rs`，与 `tests/pty/mod.rs` 一样以 `mod systemd;` 引入。
    - **目录**：根为 `/tmp/hohsd.XXXXXX`，路径短，避开 socket 路径 107 字节的上限。其下：
      - `h/`：HOME；`h/.config`、`h/.local/share`、`h/.local/state`、`h/.cache` 分别作 XDG_* 目录；
      - `r/`：XDG_RUNTIME_DIR，权限 0700；
      - `p/`：已 `git init` 并有一次提交的 fixture 项目；
      - `bin/`：`sudo` 桩（记录调用后失败），以及假 Agent。
    - **启动**：

      ```
      systemd-run --user --scope -p Delegate=yes -p RuntimeMaxSec=900 --unit=hoh-test-<pid>-<随机> --quiet --collect -- \
        env -i HOME=… XDG_*=… PATH=/usr/bin:/bin USER=… LANG=C.UTF-8 \
        /usr/lib/systemd/systemd --user --log-target=console --unit=hoh-test.target
      ```

      - 管理器的 stderr 写入 `manager.log`。
      - `hoh-test.target` 是放在 `r/systemd/user/` 的空 target，所以 `/etc/systemd/user` 等处全局启用的用户服务不会在私有管理器中启动。
      - 测试进程意外死亡时，RuntimeMaxSec 让真实管理器回收泄漏的 scope。
    - **子进程环境**：install.sh、hoh、systemctl、git 都先 `env_clear()`，再只给上述变量与测试的 PATH。不设 DBUS_SESSION_BUS_ADDRESS，`r/` 下也没有 `bus`，所以 `systemctl --user` 只能连到 `r/systemd/private`。
    - **隔离证明**（任何安装之前）：管理器本身的 `systemctl --user show -p ControlGroup --value` 在本测试的 scope 之下；不在时测试失败，什么也不装。
    - **真实环境不变**：前后各记一次真实管理器的 `list-units --all 'hoh-host@*'`，以及真实 HOME 中的 `~/.local/bin/hoh` 与 hoh-host 相关文件，断言不变。
    - **拆除**：先 `systemctl --user exit`，等 10 s；还在就向该 scope 的 `cgroup.kill` 写 1（该 cgroup 已委托给本用户）。最后断言真实管理器中没有这个 scope，再 `chmod -R u+rwX` 后删除临时根。
    - **前提不满足时**（没有 cgroup v2、真实管理器不可达、没有 linger、没有 `/usr/lib/systemd/systemd`）：测试失败并说明原因，不跳过（docs/09）。
    - **不选的方案**：
      - 在真实管理器中 `systemctl --user link` 或放运行时 unit：要改动并 reload 用户正在运行的管理器；
      - 新起一台 qemu VM：可行但太重，留给 REQ-057/066。

11. **TEST-005-06**（`tests/deployment.rs` 中的 `test_005_06_…`）

    标注 `#[ignore = "needs the candidate's release bundle: scripts/product/deployment.sh"]`。没有 `HOH_RELEASE_BUNDLE` 时，它失败而不是通过。按 AC 的 When 的顺序：

    1. 解压包，执行 `hoh/install.sh --project <fixture>`。
    2. 检查安装结果：
       - `command -v hoh` = `$HOME/.local/bin/hoh`；
       - `hoh --version` 含 `HOH_EXPECTED_COMMIT`；
       - `systemctl --user is-enabled hoh-host@<h>.service` 为 enabled，其中 `<h>` 由测试独立计算；
       - `show -p ExecStart` 的 path 为 `$HOME/.local/bin/hoh`。
    3. detach 与 attach：
       - `hoh -p 'x' --detach --output json` 以 0 退出，stdout 恰一个含 run_id 的对象；
       - host.json 的 pid 等于该实例的 MainPID；
       - `hoh attach <run_id> --output json` 以 0 退出。
    4. `systemctl --user stop` 该实例，记录 `.hoh/` 的文件树清单与哈希（路径、类型、权限、大小、内容 sha256）。
    5. `install.sh --uninstall` 以 0 退出。之后：
       - 二进制链接、`$XDG_DATA_HOME/hoh`、模板、wants 链接、env 文件都不存在；
       - `show -p LoadState` 为 not-found；
       - `.hoh/` 的清单与哈希与第 4 步相同。
    6. 全程测试进程的 euid ≠ 0，`sudo` 桩没有被调用。

    观察写入 `$HOH_EVIDENCE_DIR/TEST-005-06.json`：install 与 uninstall 的输出、`systemctl show`、detach 与 attach 的原文、卸载前后的清单、包的 sha256。

    第 4 步先停 host 的理由：运行中的 host 停止时会删除自己的 host.json、host.sock，并做 WAL checkpoint。这是 host 的正常停止，不是卸载改动了项目数据。先停下来，卸载本身对 `.hoh/` 的影响就能逐字节比较。另有一个补充测试（不带 TEST id）在 host 运行时卸载，断言：
    - 实例被停止；
    - `state.db` 的逐行内容（`iterdump` 的哈希）不变；
    - host 运行时文件之外的文件都不变。

12. **TEST-005-04**（`tests/recovery.rs` 中的 `test_005_04_…`）

    不忽略：recovery 检查与 integration 都会运行它。

    1. **夹具**：
       - 私有管理器；
       - 把 `CARGO_BIN_EXE_hoh` 与 `scripts/install.sh` 暂存成包的目录结构，执行 `install.sh --project <fixture>`（对应「已安装 hoh 与 unit 文件」）；
       - 测试的 PATH 首位是 M2-T07 测试用的假 CLI：T1 写完成 marker 后结束，T2 等一个永不出现的文件。
    2. **准备状态**：
       - 执行 `hoh -p 'x' --detach --output json`，host 由 unit 启动；
       - 按 M2-T07 测试的做法，用 SQL 预置 spec 与 READY 的 T1、T2；
       - 等到 T1 的 Attempt 为 SETTLED、effect 为 COMMITTED、marker 已写，T2 的 Attempt 为 RUNNING，且没有客户端附着；
       - 断言 host.json 的 `process_tracking` 为 cgroup（done_when 的 CR-011 一项）。
    3. **kill**：记录 `systemctl show -p MainPID,NRestarts` 与 `host_epoch`；`kill -9 MainPID`，记 t0。
    4. **等待重启**：
       - 直到 MainPID 变化、NRestarts 为原值 +1、unit 为 active，且 host.json 的 pid 为新 MainPID、`/healthz` 返回 200。这里不经客户端，否则客户端的 `systemctl start` 会抢在自动重启之前；
       - 然后 `hoh attach R --output json` 以 0 退出；
       - 再经 socket 发一个 CancelRun R，作为「重启后首个被接受的写命令」，同时清理现场。
    5. **断言**：
       - NRestarts 为原值 +1，新 pid ≠ 旧 pid；
       - host_epoch +1；
       - 本次 reconcile.completed 的 seq 小于 `run.cancel_requested` 的 seq；
       - T1 的 Attempt 行数不变；
       - T2 新增的 Attempt ≤ 1；若有，它的创建事件晚于对旧 Attempt 的 `reconcile.attempt` 判定事件；
       - 本次 `reconcile.started` 的 created_at − t0 ≤ 30 s；
       - 旧 T2 的终结证明来自 cgroup。
    6. **观察**：写入 `TEST-005-04.json`：
       - `systemctl show` 的输出；
       - `manager.log` 中与该 unit 相关的行。另外尝试 `journalctl --user -u`，结果原样记录；
       - events、attempts、effects 的导出；
       - t0 与 reconcile 的时刻。

    预期：按 ADR-022 决定 17，旧 T2 的 Attempt 为 UNKNOWN_EFFECT，不新增 Attempt，「≤1」在 0 时成立。「判定未执行之后才重投」一支由 TEST-041-01 的矩阵覆盖：产品二进制没有能让 Attempt 停在 STARTING 的钩子（CR-006 F2）。

13. **CI**（`bundle-ci.yml`）
    - **product 作业**：它已开启 linger，并等待 `systemd/private` 出现。`cargo test --workspace` 会运行补充测试与 TEST-005-04。GitHub 上 systemd 255 允许在受委托 scope 内运行 `systemd --user`（见背景中的预研）。
    - **新增 deployment 作业**：开启 linger 后执行 `bash scripts/product/deployment.sh`，超时 45 分钟。
    - **shellcheck**：bundle 作业已覆盖 `scripts/*.sh` 与 `scripts/product/*.sh`。
    - **证据**：发布证据仍只来自 VM 上 run_check 的执行记录。

## 风险与待定

1. **顺序**：TEST-005-04 依赖 M2-T07 的产品执行器，M2-T07 已合入（b1da7a6）。
2. **CI**：systemd 255 在受委托 scope 内运行 `systemd --user` 已在 runner 上验证（背景）。runner 镜像变化导致它不再可用时，这些测试失败而不是跳过（docs/09）。
3. **TEST-005-06 的哈希**：第 4 步先停 host 再取哈希。若审查认为 AC 要求 host 运行时卸载、哈希仍不变，两条规格事实上冲突：停 host 必然改动它的运行时文件。那时需要 CR-014（CR-003 D1 类：修正规格之间的不一致）来澄清 pass criteria。
4. **install.sh 的参数**：AC 的 When 没有写参数，本设计需要 `--project`。若审查要求无参调用，改为启用当前目录，不涉及契约。
5. **T2 的重投**：产品中 T2 为 UNKNOWN_EFFECT，不重投，「判定未执行后才重投」只是空真。
6. **journalctl**：私有管理器下 `journalctl --user` 不一定看得到该 unit，以 `manager.log` 与 stderr 文件代替。这只影响观察项，不影响通过条件。
7. **凭证环境变量**：环境变量形式的凭证与代理不会到达 unit 托管的 host，在 shell 中可用的 Agent 在 unit 下可能 BLOCKED_AUTH。
8. **commit 的重编**：若 cargo 不追踪 `option_env!` 的变化，包里可能是旧的 commit。TEST-005-06 会因此失败，不会假通过。
9. **XDG 不一致**：shell 与管理器的 XDG 环境不一致时，安装报错退出 69；客户端回退到 ADR-021 的拉起方式，并记录原因。

## 不变的部分

- 不改受锁文件，不改 SQL，现在不需要 CR。tests/check-plan.json 只改 deployment 一项的 argv，原本就计划由 M2-T14 替换。
- ADR-021 的启动锁、就绪判定、host 的启动顺序与 cgroup 终结证明都不变。没有 unit 时，拉起方式与以前相同。

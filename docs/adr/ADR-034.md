# ADR-034：四层 Prompt 的覆盖、来源与重放

状态：已采纳；S1–S5 已实现，S6 记录后续设计。
日期：2026-11-21
任务：M3-T03；需求：REQ-045、REQ-047。

## 背景与边界

依据 CONTRACT、CR-026 §6–8 及应用时更正、ADR-022 的职位 checkpoint、ADR-026 的装箱与同版本重放。本决定承接 `m3-t03-prep/inventory.md` 的 Q1–Q12 推荐默认与 CTO 的全部采纳决定。开发基线为 `b6681e9d230d126b133b0cc04f27267a64a0c715`，提前开发不改变任务板依赖；M3-T02 的 ADR 编号为 033，不复制其未合并实现。

合成层是职位契约、项目、任务、证据；覆盖链是 builtin、global、project、run。两者不是同一个维度。覆盖链采用整文件替换，最后一个存在且有效的层生效。事实证据与完成门禁不从职位契约的声明取得状态。

## 决定

1. 纯逻辑置于 `hoh_core::prompt`，文件读取与保存置于 core 的相邻模块；host 和客户端共用 core，客户端不依赖 hoh-app。不得新增受锁 schema、SQL、CommandKind 或检查计划条目。
2. 保留以 ` ```hoh-evidence ` 开始的 Markdown 栅栏（去掉两端空格）作为越层定义标记。按 inventory Q1 保留栅栏外的职位文本，只丢弃保留栅栏及其内容；无闭合栅栏时丢弃至文件末尾。记录 `{layer: "evidence", conflict: "cross_layer"}` 及来源；若没有剩余职位文本则拒绝装箱。链与修订摘要保留原始源文件，模板对象记录去除越层块后的文本，二者分别可追溯并支持同版本重放。合法标题 `### 证据上下文` 与 `{{EVIDENCE_CONTEXT}}` 不触发冲突；一般自然语言声明不作为门禁证据。不新增错误码。S4 复核纠正了初稿丢弃整份覆盖的偏差。
3. 变量白名单仅 GOAL、PROJECT_CONTEXT、TASK_CONTEXT、EVIDENCE_CONTEXT。未知变量在启动前以 `PROMPT_VARIABLE_MISSING` 拒绝，details 给出 variable，分类为 Decision，不重试且没有 Agent pid。部分或重复占位符保持原有 `PROMPT_UNAVAILABLE`。
4. 覆盖长度按 UTF-8 字节计，上限 32768。保存 40960 字节返回 `PROMPT_TOO_LONG` 及 bytes、limit，先校验再写，不改变旧文件；磁盘已有超长文件同样不可生效。装箱强制项预算仍由 `CONTEXT_BUDGET_TOO_SMALL` 判定。
5. global 文件为 `$XDG_CONFIG_HOME/hoh/prompts/<role>.md`，缺省 `~/.config/hoh/prompts/<role>.md`；project 为 `.hoh/prompts/<role>.md`；run 为 `.hoh/runs/<run_id>/prompts/<role>.md`。路径分量沿用 `layout::component` 对百分号与斜杠的编码，普通 UUID 不变。每个 Attempt 重新解析，不把覆盖文件钉在配置 revision。
6. `roles.<role>.prompt` 指定文件时，该文件是唯一 project 层，替代约定路径；global、run 仍包在外面。`builtin:<role>` 保留选择内置契约的语义。内置职位的约定目录链 NotFound 表示缺层；明确指定的文件缺失、自定义职位无契约、非普通文件、不可读或逃出根目录均拒绝，不静默回退。
7. 只记录存在且有效的层。RUNNING 的同一事务插入整个 `prompt_revisions` 链，`parent_revision` 指向前一层，Attempt 指向叶子。修订身份包含父修订，防止相同内容在新链上复用旧父。对象记录保留每层内容、路径和摘要，合成记录保留版本、来源、截断策略、诊断及最终文本 sha256。
8. 项目层沿用现有 specs 的 sha256、revision，追加 `docs/adr/*.md` 的路径与摘要，以及可选 `.hoh/conventions.md` 的引用；无约定写“约定：无”。无 spec 的首行保持“spec：尚无 spec”。批准规格的测试通过现有 specs 行构造，不把本仓库 requirements 当成产品规格。索引 files[] 与需求标题引用等待 M3-T02 合并后另行接线。
9. 不另存最终渲染全文；保留输入对象和 manifest，通过现有同版本 repack 得到相同字节。不放宽资源版本或装箱格式不匹配的重放拒绝。
10. 统一 diff 与三方 diff 为纯函数，不新增 diff 依赖。三方报告包括旧内置到新内置、旧内置到覆盖两份统一 diff。
11. S5 的 TUI `/settings [role]`（缺省 developer）在附着前后均为本地设置页，展示 builtin 与当前生效层的统一 diff；↑↓/PgUp/PgDn 浏览，r 恢复默认，Esc 返回。恢复仅删除 `.hoh/prompts/<role>.md`；配置明确指定的文件拒绝删除，要求先移除 prompt 配置；不改安装资源。逐级以 NOFOLLOW 打开目录句柄，最后 unlinkat 精确名称，不遍历、不匹配模式，不跟随符号链接；重复恢复幂等。预览合成与 Web Settings 不在本片。删除实现须两名互补 reviewer。
12. 后续 S6 在 StartRun 事务把内置字节存成对象，并写 resource.pinned；职位 checkpoint 无 PREPARED/STARTING/RUNNING Attempt 才推进钉。覆盖文件不钉，resource_bundle_version 的定义不变。保存基准旁路 `<file>.base.json` 记录内置摘要与资源版本，不计入契约摘要；缺旁路视为漂移。漂移事件引用三方 diff 对象。deployment 通过产品钉扎 API 种入 v1，当前二进制作为 v2，不改检查脚本或双编译。S6 涉及生命周期与并发，须两名互补 reviewer。

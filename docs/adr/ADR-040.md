## 决定

1. 模板、profiles、13 个 Skill 及 registry 与职位契约、输出 schema 共同嵌入
   `objects::RESOURCES`，参与既有资源包摘要与 Run/职位钉扎，不另建版本机制。
   解析、校验与渲染位于 hoh-core；执行与文件实例化由 host 使用核心 API；
   客户端只依赖 core，保持 ADR-031 边界。不改 SQL、受锁契约、AC 或检查计划。
2. CTO 否决 Q10 的两层缩减。Skill、模板复用 ADR-034 的文件覆盖链：builtin →
   global → project → run，最后一个存在且有效的文件生效。相对配置根分别为
   `$XDG_CONFIG_HOME/hoh`（缺省 `~/.config/hoh`）、`.hoh`、
   `.hoh/runs/<编码后的 run_id>`；其下使用 `skills/registry.json`、
   `skills/<id>/SKILL.md`、`templates/profiles.json`、`templates/<id>.md`。
   注册表按 id 合并，每层先验证完整候选集合；无效层拒绝该层并记录原因，Attempt 沿用之前的有效集合，随后仍处理更高层。
   每层同样校验；不存在表示缺层，不可读、非普通文件、逃出根目录均显式失败。
3. Skill 必填字段遵循 docs/15。依赖必须存在且无环，phase 必须属于内置已知集合，
   entry 必须可读。`output_contract` 只允许 TaskResult；声明 scheduler、dispatch、
   bypass_gates、auto_merge 能力的字段拒绝。校验失败指出成员、路径或原因。
4. 文档模板沿用七行标签：文档ID、标题、版本、状态、负责人、关联需求、来源假设，
   对应 docs/21 的七字段。元数据由输入填实，正文占位变为“待起草补充”的指引，
   只对模板原文校验占位，对结果校验字段，错误包含路径与行号。按模板 id 生成稳定文件名，先验证
   全部内容再写；已有文件保留原字节，改档只补缺。
5. 独立规格骨架写入 `docs/spec/spec.md`，不加入三档 profiles。按 ADR-033 直接
   从“用户”标题开始，含六个固定标题；用户节来自目标文本，决策与开放问题为“无”，
   需求节留空。它不套七行元数据，身份由规格索引承载。
6. `project.document_profile` 缺省 full；显式项目配置标 project，未写标 default。
   来源随配置与 Run 快照保存，实例化返回 profile/source、创建和跳过文件清单。
   S3 提供可供 S6 调用的实例化接口；本次不提前接入起草流程或伪造 effect。
7. 每个 Attempt 根据职位与阶段筛选短索引，放入 mandatory.project 的固定块。
   developer 写轮为 implement，返工为 repair；qa/reviewer 验证轮分别为 verify/review；
   监督轮为 plan；spec_draft/spec_review 分别为 specify/readiness。无法映射则为空。
   正文作为 Knowledge 条目进入既有预算装箱，不能绕过份额或通过索引夹带正文。
8. 来源、版本、原文摘要与注入状态写入 `context.packed.skills`；正文对象及独立的
   prompt_revisions 行与原有装箱记录同事务保存。Attempt 的契约修订指针保持原语义。
   重放使用记录的内容寻址对象，不重新读取后来变化的覆盖文件。
9. Round 1 撤回 Q6 的“始终注入”回退。Pi 的已探测帮助提供 `--skill`，且
   `.hoh/sessions/<session_id>/skills/<id>/SKILL.md` 与本次选定正文逐字节一致，且
   YAML 头部含非空字符串 description、可被 Pi 加载时，
   以 `--skill <session dir>/skills/<id>` 传给 Pi；短索引保留，正文不再加入
   Knowledge。能力不存在、文件不存在、正文不同或头部无效则继续知识注入、计数。
   读取错误或逃出项目的链接明确拒绝，不把它解释为已加载。只读职位的工具限制
   与禁用扩展参数保持原样；不写原生 Agent 的用户目录。
10. 旧钉扎包缺 registry 时不使用当前二进制的内置 Skill 补入；内置集为空。
    `context.packed.skill_registry` 随该 Attempt 的唯一装箱事件记录 builtin 是否存在
    和每层拒绝原因。全局 Skill 的来源使用 `global:skills/<id>/SKILL.md` 与
    `global:skills/registry.json`，不把配置根绝对路径写进索引或修订。
    注册额外字段没有已定义的扩展语义，当前允许集合为空；未知字段包括用值声明的
    scheduler 等能力均拒绝。

## 续作与 CR-034

S1 按已批准 CR-034 仅登记 architecture、recovery、requirements 三份确实提到
SQLite 的 Skill Markdown，逐项说明嵌入提示文字的用途；不改变扫描器或门禁。
续作证据位于 `.hoh-dev/self-tests/m3t08-cont/`，原红灯与 Pi 核实记录保留在 early 目录。
Pi 1.5.0 的 `--session-dir` 只指定会话存储，不能证明会话目录的 Skill 会被发现。
当时依 Q6 始终注入；此历史决定已被 Round 1 撤回，下文记录当前实现。
S6 继续等待 M3-T04 part 2；任何派发规则仍由 ADR-035 的 `admission::admit` 统一决定。

S2 的模板解析保留现有标签“来源/假设”（对应 source_refs），新增标题与负责人两行。
profiles 整文件覆盖，每层要求三档完整、full 覆盖十类、档内 id 唯一且不含路径分量，
lite/standard 是 full 子集；每层先渲染校验再接受下一层。规格骨架使用最终
`docs/spec/spec.md` 路径调用现有解析器，诊断映射回模板源路径与行号。
目标中的换行在元数据内折叠，规格用户段中去除行首空白后以 # 开头的目标行按引用文本保留，
避免输入变成结构标题；用户值中的 `{{` / `}}` 按字面保留，不重新解释为占位。不把正文指引当作已完成的事实。

S3 的文件发布在 `hoh_core::template_files`，作为 host 可调用的相邻 I/O 模块，
与 core 的覆盖文件操作保持同一边界。`Selection::from_snapshot` 读取 Run 的 project
节；StartRun 把本次 `sync_config` 已验证的 Project 经内部 RunTarget/Frozen 参数送进
同一事务，不扩大 TeamConfig 或重新读文件。旧 Run 没有 project 节时沿用 full/default。

发布先渲染整个档，再通过 NOFOLLOW 目录句柄逐级创建目录。已有普通文件原样保留，
链接、目录及 I/O 错误显式失败。每份文档用 `O_TMPFILE` 创建匿名 inode，完整写入并同步后，通过
`linkat(AT_FDCWD, "/proc/self/fd/<fd>", dir, name, AT_SYMLINK_FOLLOW)` 发布到目标名；目标已存在仍只保留原文件，最后同步父目录。
不支持匿名临时文件的文件系统显式失败，不回退到有名字的暂存文件。写入中断时
内核随句柄关闭回收匿名 inode，无需按名字清理，也消除了核对后删除的竞态窗口。
中途失败已发布的完整文件保留，重试只补缺。调用者持写租约；S6 仍负责起草入口
与 effect 对账，本片不宣称完成起草的 crash 恢复验收。

S4 的阶段取自 Assignment 所属事务读取的 Task.kind、role、writer 与监督身份；
协议修正或候选返工上下文使 developer 写轮使用 repair。短索引只含角色×阶段命中集，
正文取命中集与依赖闭包的并集，并按 id 去重；依赖 Skill 不因此混入短索引。
当前 registry 的 developer/implement 命中 domain-modeling、implementation、tdd；
准备清单所举的两项集合已过时，以资源实际字段为准。

Skill 正文全部作为 Knowledge 候选条目，命中项 relevance=100，依赖项=90，仍受
既有份额与前缀裁剪规则约束。`context.packed.skills` 的 state 是 packer 实际给出的
full/summary/reference，tokens 与 placed 分别记录原文估算和实际占用，不把引用记为
全文已注入。独立修订 ID 绑定角色、id、版本、正文来源/摘要及 registry 来源/摘要；
registry 原文另存为内容寻址对象。来源也写进 manifest.sources.skills，重放仍从原对象
取字节。RUNNING 的事务核对修订身份、对象引用及已有行一致性，再记录独立 Skill
修订；不修改职位契约链或 Attempt 的契约指针，不新增派发 gate。

S5 原先的 `native=unverified_always_injected` 已由本轮实现替换。当前装箱记录对
原生条目标 `native=pi_skill`、`state=native`、`placed=0`；tokens 是选定正文的估算，
不进入 HoH 的 Knowledge 占用。注入条目标 `native=injected`，state/tokens/placed
仍取真实装箱结果。两条路径都持久化正文与 registry 对象、独立修订；原生路径另记
项目相对 native_path。依赖闭包仍按 id 去重，只有本轮选择且匹配的会话文件才传给 Pi。

## Round 1：Skill 修复（M3O-001、002、004–008）

2026-11-23 只读运行 `pi --help`，并读取该启动器使用的安装版本标记，确认当前
Pi 为 **1.6.0**。帮助原行如下（证据 `pi-help.stdout`、`pi-installed-version.txt`）：

```text
  --skill <path>                 Load a skill file or directory (can be used multiple times)
```

无效注册不再拒绝 Attempt。每层合成在临时集合中校验，成功才采用；失败保存 layer
和原因，继续用有效层合成的集合。集成测试用无效项目层的依赖环以及不同的 global /
project 正文，直接断言假 Agent 收到 global 正文和拒绝记录。旧资源包测试将真正
钉扎的旧包移除 Skill 资源，在升级宿主后验证旧 Attempt 仍执行、索引为空且只记录
一次缺 registry；新钉扎仍沿用既有 checkpoint 升级规则。

规格审查根据 `spec_review::work_of` 的持久身份映射到 readiness；数据库的 kind
仍是 work，不再靠不存在的 spec_review kind。集成测试的隔离入口必须确认恰有
一个测试通过；错误测试名的零测试子进程现在失败。

原生路径的假 Pi 读取 `--skill` 指向的文件并留下内容记录，测试核对正文没有在 HoH
提示里重复、短索引保留、正文对象可重放，以及私有 HOME 的 `.claude` 与 Pi 扩展
树字节不变。另测无机制、无副本、正文不同、帮助无 `--skill`、超预算、越界链接与
只读启动参数。Pi 的版本与帮助核实不等于 live Agent 验收；本轮不启动 live Agent。
所有红绿与检查记录保存在 `.hoh-dev/self-tests/m3t08-fix1/`，自测，非验收。

只读核对安装包 `dist/core/skills.js` 与 `dist/utils/frontmatter.js` 后，补上原生
头部校验：Pi 会忽略缺少非空字符串 description 或 YAML 无法解析的 Skill。核心用
serde-saphyr 2.2.0（只启用 deserialize）解析头部，支持折叠文本、BOM 与 CRLF；不满足时继续知识注入，不能
把“存在同名文件”记为已加载。有效原生夹具包含真实格式的头部，无头部路径有行为红灯。


## Round 2：无特权模板发布（M3O-100）

2026-11-23 按绑定决定更正 Round 1 的 AT_EMPTY_PATH 选择：Linux 6.10 之前它要求
CAP_DAC_READ_SEARCH，Ubuntu 24.04 GA 的 6.8 内核不能依赖新内核的放宽。
改用 open(2) 文档中的 `/proc/self/fd/<fd>` 与 AT_SYMLINK_FOLLOW，仍保持匿名
inode、完整写入与同步后一次发布、不覆盖已有文件；缺少 /proc 或 O_TMPFILE 时
带明确原因失败，不使用有名临时文件。单元接缝核对实际传入 linkat 的目录句柄、
源路径和标志，并执行真实链接；另一负例模拟 /proc 不可用，断言说明与目录无残留。
两项在旧代码上均因行为断言变红，不依赖本机内核是否放宽 AT_EMPTY_PATH。
证据：`.hoh-dev/self-tests/m3t08-fix2/`；自测，非验收；未运行 6.8 内核虚拟机。

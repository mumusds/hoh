## 决定

1. 模板、profiles、13 个 Skill 及 registry 与职位契约、输出 schema 共同嵌入
   `objects::RESOURCES`，参与既有资源包摘要与 Run/职位钉扎，不另建版本机制。
   解析、校验与渲染位于 hoh-core；执行与文件实例化由 host 使用核心 API；
   客户端只依赖 core，保持 ADR-031 边界。不改 SQL、受锁契约、AC 或检查计划。
2. CTO 否决 Q10 的两层缩减。Skill、模板复用 ADR-034 的文件覆盖链：builtin →
   global → project → run，最后一个存在且有效的文件生效。相对配置根分别为
   `$XDG_CONFIG_HOME/hoh`（缺省 `~/.config/hoh`）、`.hoh`、
   `.hoh/runs/<编码后的 run_id>`；其下使用 `skills/registry.json`、
   `skills/<id>/SKILL.md`、`templates/profiles.json`、`templates/<id>.md`。
   注册表按 id 合并，每层先验证完整候选集合；无效层拒绝整个解析，不改变先前集合。
   每层同样校验；不存在表示缺层，不可读、非普通文件、逃出根目录均显式失败。
3. Skill 必填字段遵循 docs/15。依赖必须存在且无环，phase 必须属于内置已知集合，
   entry 必须可读。`output_contract` 只允许 TaskResult；声明 scheduler、dispatch、
   bypass_gates、auto_merge 能力的字段拒绝。校验失败指出成员、路径或原因。
4. 文档模板沿用七行标签：文档ID、标题、版本、状态、负责人、关联需求、来源假设，
   对应 docs/21 的七字段。元数据由输入填实，正文占位变为“待起草补充”的指引，
   渲染后校验占位与字段，错误包含路径与行号。按模板 id 生成稳定文件名，先验证
   全部内容再写；已有文件保留原字节，改档只补缺。
5. 独立规格骨架写入 `docs/spec/spec.md`，不加入三档 profiles。按 ADR-033 直接
   从“用户”标题开始，含六个固定标题；用户节来自目标文本，决策与开放问题为“无”，
   需求节留空。它不套七行元数据，身份由规格索引承载。
6. `project.document_profile` 缺省 full；显式项目配置标 project，未写标 default。
   来源随配置与 Run 快照保存，实例化返回 profile/source、创建和跳过文件清单。
   S3 提供可供 S6 调用的实例化接口；本次不提前接入起草流程或伪造 effect。
7. 每个 Attempt 根据职位与阶段筛选短索引，放入 mandatory.project 的固定块。
   developer 写轮为 implement，返工为 repair；qa/reviewer 验证轮分别为 verify/review；
   监督轮为 plan；spec_draft/spec_review 分别为 specify/readiness。无法映射则为空。
   正文作为 Knowledge 条目进入既有预算装箱，不能绕过份额或通过索引夹带正文。
8. 来源、版本、原文摘要与注入状态写入 `context.packed.skills`；正文对象及独立的
   prompt_revisions 行与原有装箱记录同事务保存。Attempt 的契约修订指针保持原语义。
   重放使用记录的内容寻址对象，不重新读取后来变化的覆盖文件。
9. Q6 的 `.pi/skills/<id>/SKILL.md` 会话目录假设须先用已安装 Pi 的帮助与源码核实。
   未证实原生加载就始终注入并计数，记录偏差；不凭文件存在推断底座已经加载。
   不访问或写入用户原生 Agent 的配置、凭据或扩展目录。测试使用私有目录和假 Agent，
   不称为 live。确认的会话目录机制才允许跳过相同 Skill 的重复正文。

## 续作与 CR-034

S1 按已批准 CR-034 仅登记 architecture、recovery、requirements 三份确实提到
SQLite 的 Skill Markdown，逐项说明嵌入提示文字的用途；不改变扫描器或门禁。
续作证据位于 `.hoh-dev/self-tests/m3t08-cont/`，原红灯与 Pi 核实记录保留在 early 目录。
Pi 1.5.0 的 `--session-dir` 只指定会话存储，不能证明会话目录的 Skill 会被发现。
依绑定 Q6 决定，始终注入并计入知识份额；不以文件存在跳过正文，原生去重验收未证实。
S6 继续等待 M3-T04 part 2；任何派发规则仍由 ADR-035 的 `admission::admit` 统一决定。

S2 的模板解析保留现有标签“来源/假设”（对应 source_refs），新增标题与负责人两行。
profiles 整文件覆盖，每层要求三档完整、full 覆盖十类、档内 id 唯一且不含路径分量，
lite/standard 是 full 子集；每层先渲染校验再接受下一层。规格骨架使用最终
`docs/spec/spec.md` 路径调用现有解析器，诊断映射回模板源路径与行号。
目标中的换行在元数据内折叠，规格用户段中以 # 开头的目标行按引用文本保留，
避免输入变成结构标题；所有最终输出仍校验无占位残留。不把正文指引当作已完成的事实。

S3 的文件发布在 `hoh_core::template_files`，作为 host 可调用的相邻 I/O 模块，
与 core 的覆盖文件操作保持同一边界。`Selection::from_snapshot` 读取 Run 的 project
节；StartRun 把本次 `sync_config` 已验证的 Project 经内部 RunTarget/Frozen 参数送进
同一事务，不扩大 TeamConfig 或重新读文件。旧 Run 没有 project 节时沿用 full/default。

发布先渲染整个档，再通过 NOFOLLOW 目录句柄逐级创建目录。已有普通文件原样保留，
链接、目录及 I/O 错误显式失败。每份文档在独占暂存文件中完整写入并同步，再用
不覆盖目标的硬链接发布；清理前核对暂存 inode，最后同步父目录。中途失败已发布的
完整文件保留，重试只补缺。调用者持写租约；S6 仍负责 effect 与崩溃对账，包括记录
并识别进程在发布前终止可能留下的暂存文件，本片不宣称完成起草的 crash 恢复验收。

S4 的阶段取自 Assignment 所属事务读取的 Task.kind、role、writer 与监督身份；
协议修正或候选返工上下文使 developer 写轮使用 repair。短索引只含角色×阶段命中集，
正文取命中集与依赖闭包的并集，并按 id 去重；依赖 Skill 不因此混入短索引。
当前 registry 的 developer/implement 命中 domain-modeling、implementation、tdd；
准备清单所举的两项集合已过时，以资源实际字段为准。

Skill 正文全部作为 Knowledge 候选条目，命中项 relevance=100，依赖项=90，仍受
既有份额与前缀裁剪规则约束。`context.packed.skills` 的 state 是 packer 实际给出的
full/summary/reference，tokens 与 placed 分别记录原文估算和实际占用，不把引用记为
全文已注入。独立修订 ID 绑定角色、id、版本、正文来源/摘要及 registry 来源/摘要；
registry 原文另存为内容寻址对象。来源也写进 manifest.sources.skills，重放仍从原对象
取字节。RUNNING 的事务核对修订身份、对象引用及已有行一致性，再记录独立 Skill
修订；不修改职位契约链或 Attempt 的契约指针，不新增派发 gate。

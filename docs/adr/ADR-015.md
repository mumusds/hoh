# ADR-015 · `hoh doctor`：探测、认证结论与输出

状态：M1-T07 采纳（CTO 设计决定，细化 REQ-006，不改变 CONTRACT 或已锁定契约）。日期：2026-11-05。

## 背景

REQ-006 规定了 doctor 必须报告的项目、protocol 与 auth_check 的取值、退出码、超时与凭证约束，但没有规定以下几点：compat manifest 放在哪里、各 CLI 用哪条非模型状态命令以及如何从输出得出结论、哪些项是“必需项”、JSON 的形状、`--live` 怎样记录尝试。以下决定填补这些空白。实现在 `crates/hoh-app/src/doctor.rs` 与 `src/doctor/`，探测命令复用 `hoh_agents::probe`。

## 决定

1. **必需项**：codex、claude、pi 三个 Agent，以及 git 和 node（≥22.19，pi 需要）。默认团队里 qa 与 researcher 用 pi，所以 pi 也是必需项。退出码完全按 REQ-006：必需项中存在 installed=false、protocol=incompatible 或 auth_check=missing 时为 3，否则为 0。node 只有确知版本低于 22.19 时才记 protocol=incompatible；`--version` 超时、失败或读不出版本时记 unknown，附诊断并列入 `summary.warnings`，不阻断（M1T07R-03）。三个 Pi 插件（REQ-048..050 可降级）、项目 `.hoh/` 的可写性、host 状态都会报告，但不影响退出码；`.hoh/` 区分四种情况：不存在时看项目目录能否写入；是目录时看它能否写入；是文件，或是指向不存在位置或指向文件的符号链接时，记不可写并说明原因（M1T07R-06）。不可写列入 `summary.warnings` 并给出处理办法。
2. **protocol**：先用 `probe::probe` 实际运行 `--version`、`--help`、子命令 `--help` 和 schema 生成。
   - 缺必需 flag 或方法（probe 报 Unsupported）记 incompatible，并列出缺项。必需项就是适配器每一轮都要用的接口，探测直接调用适配器自己的判断：`claude::interface_missing` 要求 `-p`、`--verbose`，以及说明里列有 `stream-json` 的 `--output-format`；`pi::interface_missing` 要求说明里列有 `rpc` 的 `--mode`、`--session-dir`、`--session-id`；Codex 的 App Server 要求 schema 含 `initialize`、`thread/start`、`turn/start` 请求和 `turn/completed` 通知，缺了就改用 exec，exec 要求 `codex::exec_interface_missing` 的 `--json`，两者都不可用才记 incompatible（doctor `--live` 按同一规则选传输）。只认选项的声明（M1R-03、M1T07R-14..20）：声明行缩进不超过 8 个空格，以一个或多个选项名（`-x`、`--name`，逗号分隔，可带 `=<值>`、`[=值]`）开头，后面只有取值占位（`<值>`、`[值]`、大写 `VALUE`，可带 `...`），再以两个空格或制表符接说明，或者到行尾；其余的行都是说明文字，包括续行、列表项 `- x`、`--output-format=stream-json)` 这样的提及。取值看该选项所有声明各自的说明，按整词匹配（`stream-json-v2` 不是 `stream-json`，`grpc` 不是 `rpc`）。子命令只认 `Commands:` 段命令列中的名字，换行续写的说明和后面的章节不算。Codex 是否用 App Server 由 `codex::run` 按同一接口规则决定，`Launch` 带上 schema 的请求与通知方法。能力位也用同一套判断。只影响某一轮的参数（YOLO、`--resume`、`--include-partial-messages`、`--model`）不算必需项，缺少时只让那一轮 BLOCKED_CAPABILITY。
   - 探测超时或失败记 unknown，附诊断。
   - 探测成功时对照项目的 compat manifest `<项目>/.hoh/compat-manifest.json`（结构见 `contracts/compat-manifest.schema.json`）：实现、help、schema 三个哈希都相符且兼容套件 status=PASS，才记 compatible；传输只有 exec 时记 degraded。没有 manifest、哈希不符或套件未 PASS，都记 unknown，remedy 为在没有写任务时运行兼容套件。
   - manifest 放在项目 `.hoh/` 下，因为兼容套件要在本项目的写租约空闲时运行（AC-027-04），新 attempt 也由本项目的 host 核对。
3. **auth_check 只来自原生非模型状态命令**，doctor 只取结论，从不回显原文：
   - claude：`claude auth status --json`，`loggedIn=true` 且命令成功退出记 not_verified，`false` 记 missing（未登录时 claude 以非零状态退出）。
   - codex：`codex login status`（结论写在 stderr），输出以 `Logged in` 开头记 not_verified，含 `Not logged in` 记 missing。
   - pi：`pi auth check --provider <P> --json --no-refresh`。`status=ready` 且命令成功退出记 not_verified（正向结论只采信成功退出的命令，M1T07R-12）；`status=not_ready` 且 `reason=credentials_not_configured` 记 missing。`P` 取 pi 设置文件（`$PI_CODING_AGENT_DIR/settings.json`，缺省 `~/.pi/agent/settings.json`）中的 `defaultProvider`；读不到时记 unknown，remedy 指向 `pi auth check`。`--no-refresh` 保证不改动凭证；从不传 `--credentials`，因为它会输出凭证。
   - 其他情况（命令失败、输出无法识别、超时）记 unknown。CLI 未安装或 protocol=incompatible 时不运行状态命令，记 unknown。
   - doctor 自己从不读取凭证文件或凭证环境变量的值。状态命令继承用户的环境运行，因为它要用自己的配置。
4. **超时与并行**：每条外部命令在独立进程组中运行，超时即杀整组并回收。所有命令共用一个截止时间：doctor 开始后 20 s。每条命令的时限取 20 s 与距截止时间剩余时间中较小的一个，所以先后执行的命令也不会各自再拿 20 s（M1T07R-02）。截止时间已过时命令不再启动，记为“未运行：总时限已用完”；可执行文件暂时被占用（ETXTBSY）时的重试也受同一截止时间约束，每次重试前都检查剩余时间，用完就不启动（M1T07R-11）；被总时限截短的超时也注明这一点，与命令自身的 20 s 超时区分开（M1T07R-08）。命令退出后读取 stdout 与 stderr 的等待也以同一个绝对终点为界：两次读取各自只等终点前剩下的时间，合起来不会超过时限；脱离进程组的后代进程到终点仍占着输出管道时记为超时，之后才到的输出不采信（M1T07R-13）。三个 Agent、Pi 插件查询以及 git、node 并行探测，所以即使有命令挂起或很慢，doctor 也在约 20 s 内结束（REQ-006：超时 + 5 s 以内）。
5. **子进程清单**：JSON 的 `probes` 列出 doctor 启动的每条命令的 argv、退出码、耗时和是否超时。默认模式下只会出现 `--version`、`--help`、子命令 `--help`、schema 生成、上述状态命令，以及 `pi list --no-approve`（AC-006-03 的白名单）。
6. **Pi 插件**：`config/plugins.json` 中的三个插件，安装记录取自 `pi list --no-approve`。`--no-approve` 只读用户范围、不信任项目本地文件；项目本地安装因此可能显示为未列出，这一点在 remedy 中说明。运行兼容性未经实测，一律记 unknown。
7. **host**：M1 还没有 host，记 `not_running`。
8. **输出**：`--output json` 输出一个对象并以单个 LF 结尾。顶层字段为 `schema_version`、`mode`（default/live）、`agents`（codex/claude/pi 各一项：installed、path、version、binary_sha256、protocol、protocol_detail、auth_check、capabilities、remedy、live）、`runtime`（git、node、pi_plugins、project_hoh、host）、`summary`（blocking、unverified、warnings、exit_code）、`probes`。其中 version 是原生 `--version` 的第一行原文；binary_sha256 是实际实现（而非 launcher）的 sha256。`--output text` 是同一份内容的中文可读版，每个 Agent 都列出 path、binary_sha256、capabilities，以及 live 记录（M1T07R-05）。stream-json 不适用于 doctor，按用法错误处理。
9. **`--live`**：对每个已安装、protocol 不是 incompatible 的 Agent，通过对应适配器做一次最小原生调用（不用工具，只要求回复约定口令；会产生模型费用）。三个调用并行。
   - 先向 CLI 取齐所需的一切（help 文本；codex 有 app-server 时还有它的 schema），之后才创建 attempt，所以准备失败不会留下 PREPARED 的 attempt。codex 的 `app-server --help` 不可用时按 exec 驱动，不要求 schema（M1T07R-04）。
   - 临时工作目录的 `git init`（`git -C <目录> init -q`）也走同一条有界、记日志、超时杀进程组的执行路径；它失败或超时时，该 Agent 不创建 attempt，并在 live 记录中写明原因（M1T07R-10）。
   - live 阶段另有自己的 20 s 准备时限，不沿用默认探测的截止时间，否则默认探测用完时限后健康的 Agent 也无法验证（M1T07R-07）；每一轮本身由适配器的 deadline 约束。
   - 在系统临时目录下新建的目录和其中的临时 store 中进行，不写项目数据库。临时 store 里用于挂 attempt 的 run 与 task 由 `Store::scratch_task` 建立：它只在没有任何 run 的数据库上执行，否则拒绝（`NotScratch`），什么也不写，因此不会绕过真实项目的命令路径。
   - SETTLED 且回复含口令记 verified；BLOCKED_AUTH 记 missing；其余记 unknown。
   - 每项附 live 记录：mode=live、attempt_id、原生会话 id、终态、失败原因、store 中的 attempt 行（含该会话行记下的能力：探测所得，再按本轮实际用的传输收窄，M1R-01）、原始日志所在目录。适配器的会话能力取自该 Agent 的探测结果，不按品牌写定。
   - 临时目录保留，供查看原始日志，路径写入 `summary.warnings`。

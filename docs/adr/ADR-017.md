# ADR-017 · 任务 DAG 调度、租约 CAS 与 epoch fencing

状态：M2-T03 采纳（CTO 设计决定，细化 REQ-035、REQ-037、REQ-038；新增的码与配置键见 CR-007，不改变 CONTRACT）。日期：2026-11-06。

## 背景

REQ-037 规定写租约以 CAS 取得、未获租约的任务保持 READY、授予新租约前须确认上一持有者已结束。REQ-038 规定计划校验、eligible 五项条件、分层与打分、平局规则、老化子层与参数快照。AC-035-02 要求派发提议在同一事务中取得写租约。下列各点它们没有规定，或彼此不一致：

- ADR-011 写“Attempt 与租约由 M2-T03 在实际启动时创建”，而 AC-035-02 要求租约出现在派发提议的事务里；`leases.attempt_id` 是指向 attempts 的非空外键，所以那时 Attempt 行也必须已经存在。
- 租约行在释放后删掉还是保留；“过期”是否就等于“可以再授予”。
- “调度轮”指什么；等待轮数在什么时候增加。
- 计划入库时 created_seq、layer、初始状态如何确定。

实现在 `crates/hoh-core/src/schedule.rs`（排序与选择，纯函数）、`dag.rs`（计划校验，纯函数）、`persistence/leases.rs`、`persistence/plan.rs`、`persistence/rounds.rs`，以及 `persistence/decide.rs` 的派发分支。

## 决定

1. **派发时就建 Attempt 与租约**（修订 ADR-011 §3.2 第 2 条）。
   - 派发提议被接受时，在同一事务中依次：
     1. 插入该 Task 的 PREPARED Attempt，只有行，不另写事件。它带上目标角色的 role_epoch、项目的 host_epoch 和 Run 的 config_revision。
     2. 授予所需租约。
     3. Task READY→LEASED，Run revision+1。
     4. 写一条 `decision.applied` 事件，其 payload 带 attempt_id 与租约（kind、epoch、expires_at）。
     5. 写一条派发 outbox，其 payload 也带 attempt_id 与租约。
   - 这样事件与 outbox 都恰好各一条（AC-035-02）。
   - 原来断言“派发后没有 Attempt”的单元测试改为断言恰有一个 Attempt 与一行租约。这是 AC-035-02 要求的行为变化，不是放宽测试。
2. **所需租约**：写任务（`tasks.writer=1`，含只改文档的任务）需要 `writer`。其他任务需要编号最小的空闲 `reader-k`，其中 k ≤ reader_slots，初值 2，由调用方经 `Context.reader_slots` 给出，配置解析随 M2-T07。没有空闲租约时提议 REJECTED，原因 LEASE_UNAVAILABLE（CR-007），Task 保持 READY，tasks 与 leases 不变，只写一条拒绝事件。这项检查排在其余拒绝原因之后。
3. **租约行永久保留，每次授予 epoch+1**。
   - 第一次授予时插入 epoch=1。之后的授予以 `UPDATE … SET epoch = epoch + 1 … WHERE project_id=? AND kind=? AND epoch=<读到的值>` 做 CAS，比较写在 UPDATE 本身里；改动行数不为 1 即 STALE_LEASE_EPOCH。
   - 所以同一槽位的 epoch 严格递增（AC-037-01），被新授予挤掉的持有者可以凭 epoch 认出自己已被 fence。
4. **“被占用”的定义**：未过期，或者持有它的 Attempt 尚未结束（SETTLED、FAILED、CANCELLED 之外，UNKNOWN_EFFECT 也算未结束）。
   - 单靠过期不释放槽位：旧进程可能还在运行。REQ-037 b7 要求授予前确认上一持有者已结束或已被 fence；检查进程、终止、确认回收的顺序属于 M2-T05。
   - Attempt 进入终态时，在同一事务中把它持有的租约的 expires_at 置为它的 ended_at（没有时取当前时间），租约随即可再授予。
   - TTL 为 120 s（REQ-041），续期随 M2-T05 的租约服务。
5. **无写租约不得启动写任务**（REQ-037 b2）：写任务的 Attempt 从 PREPARED 到 STARTING 时，必须持有指向它自己、且在 started_at 时刻未过期的 writer 租约，否则返回 LEASE_UNAVAILABLE，什么都不写。非写任务不受此限制。
6. **调度轮就是一次选择**（`Store::schedule_round`）。
   - 一个事务里做以下几件事：
     1. 依赖全部 ACCEPTED 的 PENDING 任务视为 READY，在本轮一并提升。
     2. 按 Run 配置快照的参数（CR-007 的 `scheduler` 键；缺键取默认 4/3/3/2、20）对候选排序。
     3. 选第一个槽位空闲的任务，按第 1 条租给新的 PREPARED Attempt。
   - 本轮写一条 `schedule.round` 事件，记下所选任务、attempt_id、租约、子层标记、age_bonus、分数（分子、分母与数值）、所用权重与 max_wait_rounds、等待的任务和被提升的任务；另写一条派发 outbox。
   - 没有可选任务时什么都不写，不计为一轮。
   - 每个 eligible 但未被选中的任务 wait_rounds+1，并在 first_eligible_seq 为空时记下本轮事件的 seq；被选中的任务 wait_rounds 归零。这些是簿记，不改 revision。
   - 只有 RUNNING、VERIFYING 的 Run 派发；BLOCKED 等状态不派发（CR-003）。
   - 能力不满足的判定与 decide 相同：角色没有 ACTIVE 绑定，或调用方没有给出该角色的 required_capabilities，或绑定会话未覆盖它们，都算不满足。
7. **排序**（`schedule::rank`/`round`，与 `tools/reference_model.py` 的 `choose` 一致）。
   - 先分层：层 0；老化子层（层 1、2 中 wait_rounds ≥ max_wait_rounds 的任务，子层内按 first_eligible_seq 先进先出）；层 1；层 2。
   - 层内按 score 降序。score =（Σ 权重·分值 + min(wait_rounds, 10)）/ max(cost, 1)，缺估计的 cost 取 3。分数按分数精确比较（交叉相乘），不用浮点。
   - 平局再按 created_seq、task_id。结果与输入顺序无关。
   - 一轮只扫描一遍候选，不排序，不读历史。
8. **计划入库**（`Store::import_plan`，`dag::validate`）。
   - 校验依次为：越界分值（在 schema 解码之前，对原始 JSON 判定，所以 user_value=7 报 SCORE_OUT_OF_RANGE 而不是一般的 schema 失败）→ schema → 重复 task_id（计划内重复、与本 Run 已有任务重名、与其他 Run 的任务重名，都是 DAG_DUPLICATE_TASK）→ 缺失依赖（依赖只能指向计划内或本 Run 的任务）→ 环（Kahn，就绪集有序；报出的环从最小 id 开始，沿最小的剩余依赖走到重复为止）。
   - 任一项失败则整个计划被拒，什么都不写。
   - 通过的计划按规范拓扑序（依赖在前，同层按 task_id）排在本 Run 已有任务之后分配 created_seq，因此与计划数组的顺序无关。
   - 被计划中其他任务依赖的任务为层 1（解阻），其余为层 2；层 0 由关键修复的来源（M2-T16/T18）设定。
   - 依赖全部 ACCEPTED 的任务入库即 READY，其余为 PENDING。
   - 写一条 `plan.imported` 事件，记下各任务的 title、状态、层与 created_seq（tasks 表没有 title 列）。Run revision+1。
9. **参数冻结**（CR-007）：对已存在的 Run 提交带 `scheduler` 的 ConfigureTeam，host 只读不写，返回 409 RUN_CONFIG_FROZEN，details.key_path="scheduler"。不存在的 Run 返回 409 RUN_NOT_FOUND。run_id 为 null 的项目级变更随 team revision 由 M2-T07 实现，在那之前返回 422。

## 不在本任务内

- 租约续期、过期持有者的检查、终止与回收，以及带 host_epoch 条件的写入：M2-T05。
- host 内的调度循环（reconcile 之后才可派发，AC-041-01）：M2-T05/T06。
- 预算预留与 next_retry_at 过滤：M2-T19（eligible 的预算一项目前取调用方给出的 budget_headroom）。
- create_tasks 决策经 decide 入库：仍按 ADR-011 §3.6 不应用。

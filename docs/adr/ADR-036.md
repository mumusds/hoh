# ADR-036 · 模式切换与运行中输入的宿主投递

状态：采纳（M3-T09 提前开发，2026-11-21）。依据为 CR-026 的 REQ-007、REQ-017、REQ-018 与 CTO 已采纳的准备清单默认决定。起点为 main `b6681e9d`；本分支不复制尚未合入的 M3-T02（ADR-033）实现。

## 范围与边界

客户端位于 `hoh-client`：只解析交互、构造共享命令、读取宿主投影。宿主语义位于 `hoh-app` 与 `hoh-core`，客户端不依赖 `hoh-app`。不扩充 shell 子命令，不修改受锁契约、检查计划或 SQL。

本轮只交付 S1–S3。S4（turn 内 steer）、S6（kill/restart 投递恢复）分别需要两名互补审查者；S5 的角色选择与 Slash 选择器留待输入通道完成；S7 的 CHANGE 必须等 M3-T02 合入。Plan 的规格起草及模式对产品任务的准入属于 M3-T04，本任务只处理切换待生效期间的写派发闸门。

## 决定

1. **SetMode 的唯一写者是命令事务。** 核对 Run 未终结、`expected_revision` 与幂等键。没有 PREPARED/STARTING/RUNNING 写 Attempt 时，更新 `runs.mode`，追加 `run.mode_changed{from,to,command_id}` 并 Touch revision；否则追加 `run.mode_change_pending`，Touch revision，返回 202。过期返回 409 STALE_REVISION。待生效期间再次提交采用后写覆盖，历史事件保留；兑现时从当前模式切到最后目标。
2. **安全点兑现。** 调度轮与写派发入口在存在未兑现 pending 时不派新写 Attempt；只读任务照旧。宿主 tick 在调度之前运行幂等模式步骤：无在途写 Attempt 即兑现最新 pending，事件 id 从 command_id 派生，Touch revision。启动对账之后也走同一步骤，不以进程内标志保存 pending。
3. **配置与 TUI。** `[ui] mode_cycle` 缺省为 `["PLAN", "BUILD", "AUTO"]`，只接受 2–3 个不重复的合法模式；加载器、快照和 example 在 S1 同提交加入并重跑 TEST-018-01。已附着的 `/plan`、`/build`、`/auto` 与 Shift+Tab 经 SetMode API 修改当前 Run，顶栏读当前 Run 模式；未附着时只改下一次由本 TUI 启动的 Run 模式，不改项目默认或发送命令。未知 Slash 不发送。ADR-031 与用户指南的旧句在 S2 同步更正。
4. **输入骑在 outbox 上。** 接受事务同时写 input_queue 与 `message_id=input_id`、`notice:"input"` 的 outbox 行。复用领取守卫、退避、代次、收据与死信；不另建传输账本。输入保持 QUEUED→DELIVERED→APPLIED/REJECTED。投递耗尽时 outbox 为 DEAD_LETTER，输入为 REJECTED，原因 delivery_exhausted。
5. **只读 ASK 与 Commander。** 普通无目标输入默认交给 Commander。按 REQ-017 行为 1/2，将 `input.queued` 加入 ADR-025 的监督事件集合，产生 normal 的 `user_input` 唤醒，键含 input_id；token、心跳、工具日志等不唤醒清单不变。只有输入投递成功才允许相应唤醒执行，提示携带问题。成功监督 turn 的最终文本作为回答写入 `input.applied{answer}`。工作态 ASK 不修改 tasks/runs 的 revision，不创建工作 Attempt；停止态命令按 ADR-031 决定 7 / E3 推进 Run revision 并以新的 `run.result` 收尾；监督 Attempt 与回答不作为任务变更决策。
6. **职位代次与首输入。** 入队载荷保存目标绑定的 role_epoch；消费时核对，迟到拒绝为 STALE_ROLE_EPOCH。session.start 未 ACKED 或新持有者仍欠首个输入时，不消费普通投递、不计数，按领取归还语义等待（M2T17R-153）。Commander 的 ASK/STEER 只进入新的监督 turn，该 turn 同时携带尚欠的首输入包；因此 session.start 已 ACKED 且没有首输入 turn 在途时可领取这类输入，不要求该 turn 先完成。首输入债务仍由 SETTLED 结清，其他职位与 HCP 消息没有此例外。Commander 自己发出的消息按 commander 绑定核对，沿用 ADR-024 决定 6（M2T17R-154），不新增例外。
7. **后续投递片的已采纳决定。** consume 的 KeyReuse 结算为一次拒绝，不重试到死信（M2T17R-254）；领取永不取验证交接。S4 将 mid_turn_steer 能力分流为 turn/next_attempt 边界；后一种统一并入下一 Attempt 的提示词，Pi 的原生输入状态机保留，产品不再单独喂数。接管后的 query/steer 路由取代 deferred，历史 deferred 不补投，改写冻结候选仍拒绝并登记 Issue。
8. **后续输入与菜单决定。** CONTROL 在接受事务内按暂停/pause、恢复/resume、取消/cancel 翻译，归一大小写与全半角空格；未知文本拒绝为 unknown_control。CHANGE 在接受后的宿主步骤复用 M3-T02 propose 的摘要、影响闭包与冲突语义，成功才 APPLIED。`/status` 显示当前状态，`/help` 显示键位，`/team`、`/model` 先显示当前值与设置范围说明；不虚构编辑能力。不增 ASK/CHANGE/CONTROL 的专用 TUI 语法，种类通过 API 表达。

## S4：投递与 Attempt 的确定性顺序（2026-11-22）

本次委派追加 S4、S6，不重写已送审的 S1–S3；S5、S7 不在本次范围。输入循环成为独立的宿主任务，沿用 Store 单写线程、outbox 领取和结算；控制循环不等待模型回执。所有角色的 ASK/STEER 都可领取，Commander 保持既有只读监督路径。

输入的 `after_attempt` 保存受理时该职位已 STARTING/RUNNING 的最大 Attempt 序号。运行中 STEER 只有在唯一目标 Attempt 的会话支持 `mid_turn_steer`、库内仍 RUNNING、epoch 相同时才预留到该 Attempt；预留在外部发送前提交。Codex runner 的 sender 属于确切 Attempt，随 turn 结束关闭；取消在适配器 select 中优先于新 steer。ASK 从不进入 steer 端口。

适配器成功回执才写 `input.delivered{boundary:"turn",attempt_id}`；Attempt SETTLED 后写 APPLIED。回执与结算的两种顺序都检查相同的持久事实。明确的 NotNow/CapabilityUnsupported 转到 `next_attempt`；明确拒绝写 REJECTED；回执丢失或超时写 UNKNOWN_DELIVERY 拒绝，不盲目再次发送外部效果。宿主在预留之后崩溃时，重投看到未完成预留也走 UNKNOWN_DELIVERY；这类外部效果未知与已写消费收据、只丢 outbox ACK 的可安全重投不同。

不支持 turn 内引导时，收据只确认路由已持久化，输入仍 QUEUED。下一次符合边界的 STARTING Attempt 在提示词构造前，通过一个 Store 事务取得输入，写 `input.delivered{boundary:"next_attempt",attempt_id}`。输入按受理顺序成为强制上下文，受原有提示词预算检查约束；相同 Attempt 重读得到同一输入，其他 Attempt 不会再次取得。完成、拒绝或取消都通过该 Attempt 的最终状态结算。首输入门仍在领取和消费两处核对。没有新建工作 Attempt 来处理 ASK。

验证者的新 query/非改写 steer 在请求事务里入 input_queue 与 outbox，响应 queued；源 Attempt 和职位 epoch 再核对，重复请求比较完整来源消息。改写冻结候选仍拒绝并开 Issue。历史 `request.deferred` 优先返回原结果，永不补投。

| --- | --- |
| 受理 → 路由 ACK → 当前 Attempt 结束 → 下一 Attempt 提示词取得一次 | `test_017_02_next_attempt_merge_has_a_durable_boundary_and_one_receipt`；`test_017_02_host_selects_turn_or_next_attempt_with_explicit_barriers` |
| turn 回执先于结算；结算先于回执；重复回执不再应用 | `test_017_02_turn_ack_and_settlement_both_orders_never_reach_a_second_attempt` |

## S6：收据、重投与进程死亡（2026-11-22）

输入收据新增不可变输入摘要（id、run、kind、目标职位、epoch、正文、来源消息），不包含 state、answer 或路由元数据。普通消费与路由消费均先核对领取信封，再读取收据；同键异文返回类型化 `KeyReuse`。S3 已有的无摘要收据仍可原样重放，但不能绕过信封核对；不迁移、不覆盖历史收据。

Dispatcher 将 KeyReuse 结算为一次终态拒绝：input 为 REJECTED(KEY_REUSE)，outbox 为 ACKED，清空退避；当前领取的计数归还，不占 `max_delivery_attempts`。`outbox.rejected` 与 `input.rejected` 使用不同的派生事件 id，重复或迟到结算不重复记录、不进死信。冲突若来自 Commander 的 decisions 历史且尚无 receipt，结算事务写一条 KEY_REUSE 拒绝回执；已有异文 receipt 保留为冲突证据，不拿拒绝结果覆盖它。

可安全重投的窗口是**消费事务已提交、outbox ACK 未提交**。收据与业务状态在同一事务内，重投返回原收据；它不再次运行消费者业务。旧代次的迟到失败不能把新代次的成功退回 PENDING。它与 S4 的外部 steer 已预留、却没有成功回执的窗口不同：后一种只能标 UNKNOWN_DELIVERY，不承诺外部模型效果恰一次。

SIGKILL 由测试注入的消费后/ACK 前 hook 在自身宿主进程触发，先同步传输日志并登记 PID 与启动标识。重启使用注入时钟跨过退避，不靠 sleep 制造窗口。父进程复用有界进程等待；等待仅观察进程结束，投递顺序由提交点保证。该测试使用产品宿主/Store/Dispatcher 和假 Commander，不调用 live Agent。诊断工件为 `input-kill9-redelivery.json`。新增测试临时目录遵循调用方 TMPDIR（本次是登记的 `/home/ai/dev/m3t09-*`），不把开发机绝对路径固化进可移植测试。

TEST-017-02 的 ignored live 入口已登记为 `steer_live::test_017_02_steer_boundaries_live`，由 `adapter-live.sh` 调用。它先运行既有的假执行器 turn/next-Attempt 屏障测试，再通过产品宿主运行安装的 Codex：前台工具连上测试持有的 socket 后等待，宿主收到 steer 的原生回执并持久化 turn 边界才释放工具。原生原始回执在 turn/completed 之前，证明对应请求先于 turn 结束；记录释放前/完成后的原始日志、摘要与原生 session。缺安装、登录或能力/兼容性条件记 BLOCKED；模型未遵守屏障协议记 FAIL。此入口本次仅编译、未执行，不能据此声明 live PASS。

S4 输入服务通过 `begun::spawn` 登记为宿主持有的任务，停止时与其子步骤一起计数并收尾。完整 workspace 测试发现原来的直接 tokio spawn 不满足既有扫描不变量后，修复了调用入口；没有修改扫描规则或允许清单。

空扫描不调用写提交 hook：`test_017_05_idle_sweeps_do_not_cross_the_write_fault_boundary` 确认没有输入状态变化时，两次扫描均不消费真实写入的故障屏障。有路由结算变化但没有其他待拒绝输入时仍提交，保留 S4 的 ACK/结算两种顺序；writer 关闭通知到达后输入循环结束，不在关闭的通知通道上空转。宿主既有的延迟提交、writer panic 和停止回归共同验证此边界。

## 首轮审查修复（M3F-01、M3F-02，2026-11-22）

停止态 ASK 原先跳过 Touch 与 result_due，在 INCOMPLETE 撞上 writer::finish 的命令守卫；BLOCKED/PAUSED 则缺少客户端所等的新结果。恢复 ADR-031 的停止态命令事务约定，运行中 ASK 的只读约定不变。`test_017_01_ask_on_a_stopped_run_publishes_a_new_result` 覆盖三种停止态、事件尾部、幂等重放及无工作 Attempt。

空闲 Run 换绑 Commander 后，普通投递等待首 turn 完成，而 user_input 唤醒等待投递完成，形成互等。Commander ASK/STEER 采用上文决定 6 的窄例外；领取和消费使用同一判定。`test_017_01_idle_commander_rebind_answers_ask_in_its_first_input_turn` 经真实换绑、会话绑定与 session.start 交付，验证 ASK 所创建的监督 turn 保留 first_input、回答一次、收据一次，未交付 session.start 与已有首 turn 的门仍关闭。普通职位首输入门的测试改用 developer，断言不变。

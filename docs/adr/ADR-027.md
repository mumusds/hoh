# ADR-027 · 冻结候选、证据有效性与三项验证检查

状态：设计审查中（M2-T10；事实按 main ab2dc29 核对）

## 背景

M2-T10 的验收是 REQ-052 的 AC-052-01 至 -05（TEST-052-01、-02、-03 属 `integration`，-04 属 `unit`，-05 属 `traceability`）；done_when 另要求 independent-qa、independent-review 两项检查经 run_check→agent_task 运行全新原生会话并产出 live-sessions.json、independent-report.json、native-attempt.json、raw-session.jsonl，traceability 检查逐条核对范围内 TEST id 的 test-results.jsonl 通过记录，三项检查不再指向 not-implemented.sh。

起点（预研笔记 `.hoh-dev/evidence/m2t10-prep/analysis.md`，按 main ab2dc29 复核：`reverify-2026-11-11.md`）：引导期工具 candidate.py、run_check.py、release_gate.py 已有冻结、前后核对与门禁的 Python 实现（受锁）；产品侧没有冻结、证据与 acceptance_results 的写者；`artifacts` 表与内容寻址对象目录已由 M2-T09 提供（`hoh_core::objects`、`persistence::runner::register`、`attempt.artifacts` 生产者事件）；`current_candidate` 被监督摘要、上下文收集与交接包共用。

## 决定

1. **模块划分。** `hoh_core::verification`（纯：候选清单、规范身份、执行记录、Evidence 与 `valid(e, c, s)` 及原因、计划查找）；`hoh_core::persistence::candidates`（SQL：插入、STALE、evidence 与 acceptance_results 行）；hoh-app 的冻结与检查驱动（git、文件哈希、经 hoh-agents 的进程底座执行）。SQL 只在 persistence（AC-062-05），`valid` 是纯函数，TEST-052-04 在 `unit`。

2. **身份。** 与 `tools/candidate.py` 逐字节相同：`CAND-` + sha256(去掉 candidate_id 的清单，键排序、紧凑、非 ASCII 不转义)。跨实现测试：同一夹具仓库，Python 算出的 id 等于 Rust 的。导出按 candidate.schema.json 校验（schema.rs 新增 loader），所以产品导出能被 candidate.py verify 与 release_gate 读。

3. **冻结。** 拒绝：未提交或未跟踪的文件（REQ-052 行为 1）；跟踪的符号链接与子模块（`git ls-files -s -z` 的 120000/160000，报出路径，失败模式 5、决定 2）；spec、environment、test plan 不是跟踪的普通文件。`.hoh/` 是 HoH 自己的状态：冻结前若 `git check-ignore -q .hoh/` 不成立，就把 `.hoh/` 写进 `.git/info/exclude`（本地、不改任何跟踪文件），否则 M2-T09 每个 turn 写的对象会让每次冻结都因“未跟踪文件”被拒（复核结论）。导出写成对象（`hoh_core::objects`），`candidates.source_path` 记它的对象路径，并登记 artifacts 行。同一 Run 内同内容再冻结返回已有 id、不新增行（决定 1）；同内容的 STALE/INVALID/REJECTED 行不复活（报错）；另一 Run 的同内容按主键冲突明确报错。插入事务里把该 Run 更早的 FROZEN/VERIFYING/ACCEPTED 候选置 STALE，写一条 `candidate.frozen{candidate_id, superseded}`；`current_candidate`（最新 FROZEN 或 VERIFYING）对它的全部读者保持一致。

4. **检查前后核对（行为 4、5，失败模式 4、6）。** 前核对逐项算出并分别命名每个不符：`checkout changed`、`worktree dirty`、`test_plan_sha256 mismatch: <path>`（与脏检查独立，AC-052-03 变体 1 要 `test_plan`）、`argv differs from the frozen plan`、`check_id not in the frozen plan`；任一不符即不运行命令、不写记录。后核对同样逐项；不符则 `source_unchanged=false`，evidence.outcome=INVALID，即使退出码为 0（AC-052-02）。

5. **执行记录与证据。** 记录字段按 execution.schema.json 1.1（受锁，不加字段）；evidence 行要求生产者 Attempt（`attempt_id` NOT NULL，外键 attempts）与一条 artifacts 行（`artifact_id` NOT NULL）：检查驱动的 API 以产出它的 Attempt id 为参数（M2-T16 的 QA/Reviewer Attempt；本任务的测试用夹具 Attempt），记录本身写成对象并登记为该 artifacts 行；Evidence = 记录 + 前后观察到的 git tree + observations（test-result 行或 AC 观察）。`valid(e, c, s)` 的原因表即 TEST-052-04 的 11 个变体：五个摘要/身份不符、observations 为空（INSUFFICIENT）、生产者 Attempt 不存在（经 `attempt.artifacts` 与 attempts 表核对）、finished<started、source_unchanged=false、stdout sha256 不符、missing_artifacts 非空；除 INSUFFICIENT 外都是 INVALID。证据有效性的原因码进事件载荷与 acceptance_results.reason；要经事件或 API 对外发出新的 ReasonCode 就需要 CR（REQ-052 决定 3：outcome 只用 INVALID，原因写 INSUFFICIENT），本 ADR 先只写进载荷与 reason 列，不改 protocol。

6. **acceptance_results。** 检查驱动为每条映射到本 Run spec 中某 AC（TEST 编号同号，且该 AC 的 check_id 等于本检查）的 test-result 行写一行：PASS/FAIL/DEGRADED 照写，SKIPPED 记 NOT_RUN；无效证据的每一行记 INVALID。行只追加（M2-T18 在其上投影）。

7. **产品位置（行为 8）。** 记录与原始输出在 `.hoh/evidence/<candidate>/<check>/<record>/`（只追加、在被忽略的 `.hoh/` 下），stdout/stderr 与声明的工件写成对象并登记 artifacts 行与生产者事件（复用 M2-T09）。

8. **traceability 检查。** `bash scripts/product/traceability.sh <profile>`（v0.1 起，M7-T04 改为 v1）：在 `$HOH_EVIDENCE_DIR` 外查找绑定本候选（清单引用 path+sha256、candidate_id、spec 一致）的最新有效记录（退出 0、source_unchanged、未超时、无缺失工件），每个范围内 TEST id 的场景检查记录须有至少一行且全部 PASS；报告 `traceability-report.json{candidate_id, profile, tests:{id: {check, record_id, passing}}, missing}`；退出 0 当且仅当 missing 为空。TEST-052-05 由脚本先跑的夹具自测（临时仓库：候选 C 全齐、C' 删去一个 v0.1 AC 的测试并重新冻结）写出；traceability 自身是场景检查的 TEST id 由本次运行的自测行满足。门禁不读这份报告（release_gate 受锁）：在 docs/22 写明，v1 发布前由 M7-T04 把 argv 改成 v1。

9. **independent-qa / independent-review。** 一个脚本 `bash scripts/product/independent.sh qa|reviewer`：上下文 JSON 由助手从 `$HOH_CANDIDATE_FILE` 与 traceability 同法找到的检查记录生成，用 tools/render_prompt.py 渲染；`agent_task.py --output-dir "$HOH_EVIDENCE_DIR/attempt" --report-out "$HOH_EVIDENCE_DIR/independent-report.json"`；再把 attempt.json、stdout.jsonl 复制为 native-attempt.json、raw-session.jsonl 并核对与报告引用的 sha256 一致；退出 0 当且仅当报告 PASS 且无 critical/high，1 为 FAIL/UNKNOWN 或桥失败，3 为没有可运行的 Agent（BLOCKED）。Agent 与回退：qa 先 pi 后 claude，reviewer 先 codex，再 codex `--model gpt-6.1-sol`，再 claude；grok 被 agent_task 在检查内拒绝。提示词写明唯一可写的目录是 `$HOH_EVIDENCE_DIR/observations/`（桥会隐藏该变量，所以写成字面路径）。CI 没有认证，只跑带假 CLI 的套件测试；假 Agent 的结果永不报为 live。

10. **范围之外。** 把检查驱动接进 QA/Reviewer Attempt、cgroup 跟踪与 barrier 属 M2-T16；冻结候选相对基准的改动文件（ADR-026 决定 12 的代码来源）也属 M2-T16，本任务在 `candidate.frozen` 事件里记下冻结时的 HEAD 父提交作为基准，供它使用。

## 实施切片

S1 verification 类型与身份（跨实现测试）；S2 `valid` 与原因（`test_052_04_*`）；S3 persistence::candidates（幂等、不复活、STALE、事件）；S4 冻结驱动（`test_052_01_*`，符号链接、子模块、`.hoh/` 排除）；S5 前核对（`test_052_03_*`）；S6 执行、后核对、证据与 acceptance_results（`test_052_02_*`）；S7 traceability 脚本与套件测试；S8 independent 脚本与套件测试（假 CLI）；S9 docs/22、计划条目、validate_bundle；S10 候选、检查（traceability 在本任务候选上预期非零，TEST-052-05 由自测 PASS；independent-* 真实会话，缺认证即 BLOCKED）、审查。

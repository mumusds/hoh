# ADR-012 · Codex 适配器的协议细节

状态：M1-T04 采纳（CTO 设计决定，细化 REQ-024，不改变 CONTRACT 或已锁定契约）。日期：2026-11-04。

## 背景

REQ-024 规定了 App Server 优先、exec 降级、取消、steer 与鉴权失败的行为，但以下几点没有写死：服务端请求按 headless 策略怎么回答，哪些通知算"未知"，turn/completed 之前 EOF 时 FAILED 与 UNKNOWN_EFFECT 怎么区分，steer 的输入何时算 APPLIED，以及降级时 Attempt 处于哪个状态。实现在 `hoh_agents::codex`。

## 决定

1. **未知通知**：以该 CLI 版本 `codex app-server generate-json-schema` 的 `ServerNotification.json` 列出的方法为已知集合（0.166.0 共 85 个）；不在集合内的通知原样存为 `adapter.unknown_event`，不 panic。跨适配器的已知帧登记由 M1-T07 补齐。
2. **服务端请求（headless）**：收到即答，并记 `adapter.server_request` 事件。命令/文件审批回 `decline`，旧式 `execCommandApproval`/`applyPatchApproval` 回 `denied`，MCP elicitation 回 `decline`；需要人做选择或需要凭据的请求（`item/tool/requestUserInput`、`item/permissions/requestApproval`、`item/tool/call`、`account/chatgptAuthTokens/refresh`、`attestation/generate` 及未知方法）回 JSON-RPC 错误 -32000。不伪造任何人的选择。
3. **终态判定**：取消 > 超大帧 > deadline > 原始日志不完整 > 协议请求被拒（initialize/thread/turn 出错）> turn.status。completed → SETTLED；interrupted → CANCELLED；failed → FAILED，codexErrorInfo=unauthorized（或 exec 的 `unexpected status 401`）记 BLOCKED_AUTH 且不重试，rateLimitExceeded/serverOverloaded 记 TRANSIENT_EXTERNAL，交给 M2-T19 的重试策略持久 next_retry。turn/completed 之前流结束：若已有可能产生副作用的条目开始（命令、文件改动、工具调用等非纯文本条目）记 UNKNOWN_EFFECT，否则 FAILED（PROTOCOL_INCOMPLETE）。App Server 的退出码不参与判定（turn 结束后由 HoH 关闭 stdin），exec 的退出码参与。
4. **steer**：有活动 turn 时发 `turn/steer`（expectedTurnId 默认取活动 turnId，调用方可指定），原生回应成功 → DELIVERED，该文本的 userMessage 条目出现 → APPLIED，原生拒绝 → REJECTED（原因记入事件）。turn 尚未开始时先暂存，开始后发出；turn 已结束或进入降级时输入保持 QUEUED，exec 模式回 CAPABILITY_UNSUPPORTED。
5. **降级**：Attempt 在握手完成前保持 STARTING；initialize 返回 -32601 或超时则关闭 App Server，记一条 `adapter.degraded`，再以 exec 运行同一 Attempt（STARTING → RUNNING 记 exec 的 pid）。原始日志分别为 `app-server.*` 与 `exec.*`。
6. **取消**：活动 turn 上先发 turn/interrupt，等待 native grace（初值 10 s）内的 interrupted 终态，超时再对进程组 SIGTERM → SIGKILL；turn 未开始时直接终止进程。终态经 Attempt 的 CancelLatch 提交（ADR-011 §2，M1T03R-10）。exec 模式以 SIGINT 作为原生取消。

## 未采用

- 用固定的帧名单判定未知通知：随版本漂移，改用该版本自己的 schema。
- 对 requestUserInput 回空 answers：形式上合法，但等于替人作答，改为回错误。
- EOF 一律 FAILED：命令可能已在执行，后果未知时记 UNKNOWN_EFFECT 交给 reconcile。

## 已知限制

codex 0.166.0 与 claude 2.1.318 都把工具命令放在独立的进程组里。原生中断（turn/interrupt、SIGINT）会由 CLI 自己结束这些命令；若升级到对 CLI 进程组 SIGKILL，组外的后代进程可能残留。live 检查会把仓库内任何残留进程判为 FAIL；进程底座的后代追踪留待后续改动。

# ADR-014 · M1 的 TUI 外壳：终端恢复、输入历史与无 host 时的行为

状态：M1-T08 采纳（CTO 设计决定，细化 REQ-001 中 M1 范围的部分，不改变 CONTRACT 或已锁定契约）。日期：2026-11-05。

## 背景

REQ-001 要求 `hoh` 在 stdin 与 stdout 都是 TTY 时进入 Workspace TUI（alternate screen + raw mode），并做到：持久化项目级输入历史、Ctrl+R 检索；正常脱离、SIGTERM 或 panic 时恢复终端；无 TTY 时以 64 退出。M1-T08 只交付外壳：进入 Workspace（无 host 时显示离线）、输入历史、SIGTERM/SIGHUP/panic 后的终端恢复、tui-pty 检查脚本和 AC-001-03。连接 host、提交 StartRun、从 DB 投影恢复 run 状态（AC-001-01/02）归 M2-T13；配置解析（`default_mode`）归 M2-T07；doctor 同源的检测引导要等 doctor（M1-T07）。以下决定填补文档未规定的部分。实现在 `crates/hoh-app/src/tui.rs` 与 `src/tui/`。

## 决定

1. **库与事件循环**：Ratatui 0.30.2 加其 Crossterm 0.29 后端（CONTRACT 第 2 条）；ratatui 关闭默认特性，只开 `crossterm`。crossterm 负责绘制和切换终端模式（raw mode、alternate screen、bracketed paste），但不用它读输入：它的事件读取从不启动。原因是 crossterm 0.29 的读取有三个无法绕开的问题：终端挂断后输入读到 EOF，它会无限重试 0 字节的读取，进程永不退出并占满一个 CPU（M1QA-01）；读到不完整的转义序列（如 `ESC [`）后，它在阻塞的 read(2) 里等后续字节，期间看不到信号；进入的读取无法取消，所以放到单独线程里也会在交还终端后读走 shell 的下一条输入（M1T08R-12、-13、-14）。因此事件循环是单线程的：每次最多在 stdin 的 poll(2) 上等 100 ms（信号会提前结束等待），检查信号标志后，只读取 poll 报告已到的字节，由 `tui/input.rs` 自己解码成与 crossterm 解析器相同的 `Event`（Workspace 用到的键：字符及 Ctrl/Alt 组合、Enter、Tab、Backspace、Delete、Home、End、方向键、Esc，以及括号粘贴）。单独的 ESC 后只再等 30 ms，没有后续即 Esc 键；已经开始的序列（`ESC [`、`ESC O`、粘贴标记、分几次到达的 UTF-8 字符）最多再等 500 ms，因为慢速链路可能把它拆开（M1T08R-20），信号仍会立即结束等待。等满仍不完整时，ESC 加一个字节是 Alt 组合，更长的残缺序列丢弃；残缺的粘贴和 UTF-8 字符继续等。Linux 控制台的 F1–F5（`ESC [ [` 加一个字母）和 X10 鼠标报告（`ESC [ M` 加 3 个原始字节）整段跳过，不当作输入（M1T08R-16、-17）；粘贴的结束标记只在新到的字节里找，长粘贴的解码是线性的（M1T08R-18）；编辑器从光标往回累计显示宽度来决定显示哪一段，长行的每次绘制也是线性的（M1T08R-31）；显示哪一段和光标所在列都按 ratatui 绘制时的单元格宽度计算：逐个字素取 `CellWidth`，控制字符不占格。这样光标总落在光标前最后一个字素之后的那一格，阿拉伯文 lam-alef 这类整段宽度小于逐字素绘制宽度的文字也是如此（M1T08R-34）。poll 报告有输入后、读取之前再检查一次信号标志，所以绘制被阻塞（终端输出被暂停）期间到达的信号也不会让循环读走之后敲下的输入（M1T08R-19）；一次读到的一批事件逐个处理，每个事件之前都检查信号，长批次（每个 Enter 都写历史）不会拖延退出（M1T08R-21）。kitty 在 legacy 模式下也会把部分组合键（如 Ctrl+Shift+R）发成 `CSI 码点 ; 修饰 u`，按 crossterm 的规则解码（M1T08R-23）：码点必须是合法的 Unicode 字符，带 alternate 时也一样（M1T08R-29）；所有 CSI 键修饰参数后的事件类型（`:2` 重复、`:3` 释放）都按数值读取并保留，释放的键不会被当作按下（M1T08R-28）；修饰参数不是数值（为空或超过 255）时，与 crossterm 一样按无修饰的按下处理（M1T08R-35）；Alt 加一个分几次到达的 UTF-8 字符与单独的字符一样一直等到完整（M1T08R-24）。poll 报告 POLLHUP/POLLERR 或读到 EOF 即终端已断开，按终端失败结束。窗口大小变化由 SIGWINCH 标志触发重绘。主循环一结束（包括 panic）就不再有任何读取，所以用户离开之后、恢复期间敲下的输入留给 shell。信号用 `signal-hook` 的 `flag` 接口登记，这样不需要自己写 unsafe 代码。后续 TUI 接入 host（M2-T13）时再换成异步循环。
2. **终端恢复只在一处**：进入时依次开启信号标志、panic hook、raw mode、alternate screen、bracketed paste；恢复时依次关闭 bracketed paste、退出 alternate screen、显示光标、关闭 raw mode。进入和撤销用到的每条转义序列各自跟踪。一条撤销序列要等它所撤销的进入序列完整写出后，才标为待发送；所以从未进入 alternate screen 的终端不会收到“退出”，那会把旧的保存光标恢复出来（M1T08R-09）。已经写出的序列不会再写一次：第二次退出 alternate screen 会把光标恢复到保存的位置，盖掉之后打印的内容（M1T08R-07）。写到一半中断的序列，下次从头重发，前面加一个 CAN（0x18）。这里只依赖 CAN 对外壳自己所发序列的作用：外壳只发 CSI 序列，CAN 会终止正在解析的 CSI（VT100 及其后继、xterm、VTE、tmux），在 ground 状态下不起作用。OSC、DCS 中各终端对 CAN 的处理不一（tmux 会应用部分 OSC 标题，DCS 之后的文字仍会被吞），所以外壳不发这两类序列（M1T08R-11）。画面帧写断时同样记下，打印诊断前一并用 CAN 了结。每一帧都给 ratatui 一个光标位置（选择框打开时放在选中项上），ratatui 因而从不隐藏光标，析构时也没有要恢复显示的光标；否则它的析构会在恢复流程之外写终端，失败时直接打印到 stderr（M1T08R-10）。写断的进入序列不再补完，只发一个 CAN 了结。打印任何诊断之前先发 CAN，所以文字不会落进写断的序列里（M1T08R-08）。raw mode 单独一个标记，屏幕失败时照样交还（M1T08R-01）。序列写到 stdout 的一个无缓冲副本；TUI 画面通过自己的缓冲写出，被丢弃时缓冲内容不写，所以进程的 stdout 缓冲里不会留下 TUI 的字节、在恢复之后才被写出。进入的第一步之前就交出守卫，只完成一半的进入同样会被撤销（M1T08R-05）。正常退出时恢复最多尝试三次，结果决定退出码；panic hook 同样先重试，再打印诊断和 panic 消息。正常脱离、信号和 panic 都走同一个恢复函数。raw mode 由 crossterm 记下进入前的 termios，恢复时原样写回，所以 `stty -g` 与启动前一致。panic hook 先恢复终端，再调用原 hook，这样 panic 消息会出现在正常屏幕上。
3. **退出码**：正常脱离为 0，SIGINT 为 130，SIGTERM 为 143（REQ-004 的表）。SIGHUP 不在 REQ-004 的表里，选用与前两者同一规则（128 + 信号号）的 129，加到 `exit.rs` 的客户端事件中。TUI 运行中终端读写或模式切换失败时，或者退出时终端未能完全恢复（stderr 提示可运行 `stty sane` 或 `reset`），都以 74 退出，不报 0（sysexits 的 EX_IOERR，与 64/69/78 同一族），同样加到 `exit.rs`；终端被关闭（关窗口、SSH 断线）时：它是控制终端，内核会发 SIGHUP，以 129 退出；它只是 stdio、不是控制终端，没有信号，按终端失败以 74 退出。只要收到过信号，所有退出路径都以信号的退出码为准：挂断也会让终端读写失败；用户选了脱离、信号在恢复期间到达，同样如此（M1T08R-06）。panic 沿用 Rust 的 101。写 stderr 的提示本身失败时（终端已挂断、设备已满）忽略该失败，不改变退出码：`eprintln!` 写失败会 panic，把退出码变成 101，所以面向用户的提示都改用忽略写入错误的 `say!`（M1QA-01）。raw mode 下 Ctrl+C 是按键，不是 SIGINT。
4. **无 TTY**：stdin 或 stdout 不是 TTY 时，不进入 TUI、不读 stdin；按用法错误以 64 退出，stderr 提示改用 `hoh -p`，stdout 为空，不创建或打开 `.hoh/`。
5. **无 host 时的 Workspace**：M1 没有 host，所以顶栏显示 `host 离线`，run 显示“无”，baseline 显示“未知”（不读 DB，不猜测），mode 显示内置缺省值 `AUTO`（配置解析器到位前不读配置文件）。
6. **Enter 与输入历史**：在 M1 中按 Enter 只把这一行追加到项目级历史 `.hoh/input-history.jsonl`（每行一个 `{"text": …}` 对象；`.hoh/` 不存在时创建），并在对话区说明“host 离线，未发送”，不写 commands/runs/tasks/input_queue，也不冒充已下令（docs/03“不能显示已下令实际丢失”）。只打开 TUI、不按 Enter，不会写任何文件。历史文件中无法解析的行会被跳过，不阻止 TUI 启动；读不了的文件会显示提示，TUI 照常使用空历史。文件最后一行没有换行时（写到一半崩溃或手工编辑），追加前先补一个换行，新记录自成一行（M1T08R-02）；两个外壳同时这样做只会多出一个空行，读取时跳过。
7. **编辑与检索的键位**（docs/03）：
   - 光标按 grapheme 移动，按显示宽度定位；插入或删除让相邻字符并成一个 grapheme 时（零宽连接符、组合符），光标移到该 grapheme 的末尾，始终落在整段文本的边界上（M1T08R-03）。
   - Up/Down 浏览历史。
   - Ctrl+R 进入反向增量检索：输入的文字缩小匹配范围，再按 Ctrl+R 换更早的一条，匹配行直接显示在编辑器里。Enter 只结束检索并保留匹配行，不发送；Esc 取消检索，恢复检索前的草稿。
   - Ctrl+C：编辑器非空时清空；为空时打开“脱离 / 暂停 / 取消任务”选择。M1 没有 run，所以只列出“脱离”。Esc 关闭这个选择。
   - 粘贴走 bracketed paste，其中的换行在 M1 合并为空格；多行编辑归 REQ-015（M4）。
8. **测试入口**：只在 debug 构建（`cfg(debug_assertions)`）中，环境变量 `HOH_DEBUG_TUI_PANIC` 让 TUI 在首次绘制后 panic，供 PTY 测试检验 panic 后的恢复；`HOH_DEBUG_TUI_RESTORE_GATE=<路径>` 让主循环结束后以及 panic hook 中、交还终端之前停下，在 stderr 说明，直到该路径存在，供 PTY 测试先在这段时间里输入、再放行，从而确知输入发生在恢复之前（M1T08R-15）；10 s 内未放行就 abort，测试因此失败而不会空过（M1T08R-22）。release 构建没有这些入口。
9. **tui-pty 检查**：`scripts/product/tui-pty.sh` 在 PTY 中运行 `crates/hoh-app/tests/tui_pty.rs`。PTY 由测试用 rustix 打开；`setsid --ctty` 让 hoh 以该 PTY 为控制终端。测试比较前后的 `stty -g`，检查退出码和退出 alternate screen 的转义序列。脚本照常写 `test-results.jsonl`。M1 的 PTY 测试不对应任何 TEST id（TEST-001-01/02 归 M2-T13），所以该文件在 M1 可以没有 AC 行；脚本仍要求至少执行并通过一个测试。

## 验证

- `crates/hoh-app/src/tui/tests.rs`：编辑器、历史与检索、按键处理和 TestBackend 渲染。
- `crates/hoh-app/tests/tui.rs`：TEST-001-03，integration 检查。
- `crates/hoh-app/tests/tui_pty.rs`：进入 Workspace、历史跨会话可检索、正常脱离、SIGTERM、SIGHUP、panic 后的终端恢复，终端在运行中被关闭（作为控制终端 129，只作 stdio 74），脱离、残缺转义序列后收到信号、panic 三种情况下恢复期间输入的内容都留给 shell，一次连按 5000 个键（超过一次 4 KiB 的读取）全部收到，不按键时窗口大小变化也会重绘，终端输出被暂停期间收到信号后输入的内容留给 shell，被慢速链路拆开的序列和粘贴起始标记仍完整识别，128 KiB 的粘贴立即画出，tui-pty 检查；`src/tui/input.rs` 的单元测试覆盖解码规则（含 Linux 控制台功能键、X10 鼠标报告、分块到达的长粘贴）。

# 开发计划与依赖

机器任务板：`contracts/development-tasks.json`。24个工作包，每个包包含可再拆分的小增量。每个milestone的全部需求通过后才进入整体发布资格，不将负责人角色当成只允许此人写代码。

|阶段|主要产物|出口|
|---|---|---|
|M0|基线审核、实际CLI探测、版本锁、Rust workspace|包检查通过+真实环境记录；缺认证记录外部阻塞|
|M1|三Agent原生适配、最小命令面、基础TUI|mock契约和真实smoke分开；取消与输出通道正确|
|M2|SQLite/outbox/leases、HCP、工作流与监督、QA/Review barrier|crash/replay测试；最小任务闭环且无错误验收|
|M3|规格/CR/追踪、Plan对话、Prompt/Skill/模板|从需求到任务再到实现/验收的全链路|
|M4|Workspace/Team/Focus/Timeline、状态栏、终端交互|真实PTY、宽度/Unicode、大日志快照|
|M5|三插件、严格证据、回归/Flaky、恢复迁移|真实插件RPC与长上下文测试；门禁负例|
|M6|Web全工作台、双端控制、安装/升级/交付|浏览器与新VM部署、冲突与重连|
|M7|三Agent真实工程、72h soak、完整验收|所有required证据有效；否则INCOMPLETE|

## 每个工作包的执行契约

先读相关REQ/AC和模块文档；先建立失败测试/边界，然后最小实现、局部测试、代码审查；以coherent行为形成commit。记录候选、未解决问题、依赖与下一步，不在最后只写“已做完”。采用feature branch，不在main直接进行大改。

M0发现协议与文档不一致时查询官方对应版本并补兼容记录，不将设计硬改为另一框架。模型名使用本机实际默认配置，不把聊天示例GPT型号写入核心代码。

## 并发策略

开发主写者Claude；Pi可独立研究/测试已冻结版本；Codex审查并监督。文档作者与代码作者同时写同repo也需遵守写租约，不能以“只改docs”绕过冲突控制。短的只读研究允许并行，但研究上下文不得阻塞需要空闲QA槽的最终验证。

## 交付颗粒度

每阶段输出 milestone report：REQ状态、实际命令、失败证据、candidate identity、review、变更说明。达到阶段出口后继续下一包，不在M1停下来请求是否继续。发生真实授权/认证/预算阻塞时保存恢复点，不能假装继续。

## 自举切换

M0–M2可由外部Codex调用单次原生CLI桥完成；桥不是生产调度器。M2成熟后选择小task由新HoH执行并与外部结果比对。禁止直接让未通过幂等与证据测试的新HoH接管整仓写入。

## 范围控制

新增平台/多机/插件商店进入future backlog，不替代已承诺Web或角色自定义。若性能门槛需要修订，提交有基准证据的CR，不能为了“生产完成”自行降低。用户已明确采纳的细节不再重复询问。

## 外部阻塞与可继续工作

M0-T03真实认证/协议采样可因外部账户阻塞；M1的类型、离线adapter fixture和CLI不依赖它，仍可继续。M5-T01真实Pi组合依赖M0-T03，但M5-T02证据/回归工程可从M4-T03继续；M7真实验收再汇合所有live前置。不得让一个缺账号阻塞所有无关开发，也不得把blocked任务改为done来解锁验收。
